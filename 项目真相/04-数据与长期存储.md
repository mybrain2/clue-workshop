# 数据与长期存储（当前实现）

> 更新至 0.7.7。本文替代早期 IndexedDB/PostgreSQL 设想；当前实现没有服务器，也不使用 PostgreSQL。

## 存储定位

- 本地优先、单机 SQLite。
- 一个案件一个图数据边界；同值对象跨案件不自动合并。
- UI、CLI、MCP 必须共享同一 `case_core`，不得直接修改数据库绕过快照或 revision。

## 真实目录

```text
~/Library/Application Support/线索研判数据/
├── casework.sqlite3
├── attachments/       # 当前仅作 OCR 临时目录与未来附件预留，尚无正式附件模型
├── exports/           # 默认导出目录
├── backups/           # 预留；尚未形成自动备份产品能力
├── snapshots/         # 预留目录；撤销快照当前存 SQLite 表
└── logs/desktop-runtime.log
```

应用升级或重装不主动清理该目录。永久删除只允许回收站案件且要求案件标题匹配；CLI/MCP 不暴露永久删除。

## 实际 schema

```text
cases
- id, title, archive_title, archive_folder
- background, police_disposal, current_status, path_lanes
- status: active | archived | trash
- sort_order, archive_note, root_id
- created_at, updated_at, archived_at, trashed_at

entities
- id, case_id, kind, label, display_name
- status, role, note, accent, pinned, custom_type

relations
- id, case_id, source_id, target_id
- label, spread, status, note, emphasis

case_operations
- 审计式操作描述和时间

case_snapshots / case_redos
- 撤销与重做用的案件图 payload

workbench_meta
- revision：CLI/MCP 写入后供桌面端轮询刷新
```

对象种类：`subject`、`wechat`、`qq`、`phone`、`ip`、`location`、`datacenter`、`device`、`group`、`platform`、`organization`、`custom`。

## 已实现规则

1. 同案内按对象种类和值复用实体；这不是身份认定。
2. 增加/更新/删除实体关系前保存快照，支持撤销/重做。
3. 位置与机房仍是普通实体关系，但图谱投影为来源对象附属卡。
4. 归档只改变案件状态与归档分类，不删除图数据。
5. 导出案件包时写入完整 CaseDetail；导入时创建新案件 ID，不覆盖已有案件。
6. 外部 CLI/MCP 写入会更新 revision；桌面端约两秒轮询并刷新。

## 当前风险与后续

- 未实现附件对象、哈希、来源关联、附件删除策略。
- 未实现数据库或案件包加密；本地目录不等同于加密保护。
- 未实现导入批次 ID、导入审计和单批次回滚。
- 未定义正式备份/恢复 UI 与灾难恢复验收。

这些事项见 `43-全量产品与工程复盘.md` 的 P0 建议。
