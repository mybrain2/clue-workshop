# 101 - 2026-09-24 图谱"连线乱"调研结论与 0.7.14 发布确认

## 用户问题

用户在呜呜呜呜案件依次导入好友列表 → 加群列表 → 群成员后，图谱突然显得"连得很乱"，要求查清原因并用最简单的话解释。

## 调研方法与证据

全部结论来自 SQLite 数据库实测（`~/Library/Application Support/线索研判数据/casework.sqlite3`），非代码推理。

### 案件构成实测

呜呜呜呜案件：1052 实体 / 1152 关系，孤立实体 0 个。

| 中心节点 | 数据 | 来源批次 |
|---|---|---|
| QQ `2091181488`（L） | 加入群 496 条边 | **2026-09-20 16:57 `ai群.csv`（496行）**——不是今天的导入 |
| QQ `2128667131`（张世豪） | 好友 500 + 加入群 36 + 绑定手机号 | 2026-09-24 10:14 好友列表 + 加群列表 |
| 群 `548360752`（相亲相爱一家人） | 群成员 100 条边 | 2026-09-24 10:15 群成员表 |

### 交叉实测（"乱"的三个真实来源）

1. **两个中心共享 7 个群**：张世豪的 36 群与 L 的 496 群交集 7 个（世豪有限公司-重新扬 ×2、相亲相爱一家人、家居建材代理批发通知、北流_商品圈样品图、世豪连锁快递-货到付、漏网之鱼の项目组）。今天的导入把两条原本独立的链缝合到一起。

2. **好友表与群成员表是同一批人的两个视角**：相亲相爱一家人的 100 群成员中 **90 个同时是张世豪的 500 好友**。每个 QQ 节点身上挂两条边（好友+群成员），被两侧拉扯，连线交叉。

3. **历史数据叠加**：9-20 导入的 496 群数据一直躺在案件里，今天任何新导入在视觉密度上都是叠加在其上。

### 结论

数据全部正确连接：零孤立实体、零重复节点、零未连接对象。**"乱"不是 bug，是"同一批人既是好友又是群成员"+"两个中心共享 7 个群"的真实交叉形态，叠加旧数据仍在案件里。**

给用户的建议：测试"依次导入好友→加群→群成员"的形态时，新建空案件再导，避免与 9-20 历史数据叠加。
