# 61 - 2026-09-07 结构化线索表格底层适配调研

## 1. 需求判断

群列表、好友列表、QQ同机表和手机号绑定QQ不是“批量创建一列节点”。它们同时包含对象、关系、关系属性、对象属性、查询上下文和原始来源。继续把每行压成“节点 + 备注”会丢失结构和证据边界。

本轮只完成调研和设计，未修改数据库、源码或用户数据。实施前必须先确认底层迁移和模板语义。

## 2. 四份脱敏表格画像

- 群列表：496 行。完整字段有查询人角色、群备注、群名称、群人数、最后消息、创建时间、简介和公告；解密账号列因脱敏为空。
- 好友列表：2255 行。完整字段有分组、昵称、好友备注；查询账号和好友解密账号为空。
- QQ 同机表：75 行。完整字段有相似度、关系证据、昵称、注册地及多项状态/风险字段；UIN为空。
- 手机号绑定 QQ：11 行。完整字段有手机号类型和设置/修改/验证时间；QQ和手机号为空。

因此可以验证表头、字段类型和噪声分布，但不能用这些副本验证真实账号去重和完整图生成。缺少端点主键时必须阻止提交，不能使用昵称、群名或备注造节点。

## 3. 范围纠正与适配结论

用户明确收敛范围：本产品不负责来源证据管理，也不负责推断。表格由用户手工粘贴或导入，分组、备注和角色含义均由人判断；程序只负责忠实保存、展示、录入和批量映射。

采用“现有核心对象/关系 + 结构化属性”的本地 property graph：

- 现有 `entities` 和 `relations` 继续保存稳定图事实。
- 为对象和关系增加结构化属性表，支持文本、数字、时间、枚举和列表；不把所有字段塞进备注。
- 不新增来源证据、置信度、推断状态、自动角色判断或复杂 Claim/RawRecord 工作流。
- 分组、好友备注、查询人角色等按用户提供的原值保存；系统不解释、不推断、不覆盖对象全局角色。
- 批次仍只负责导入统计、重复处理和整批撤销。

参考成熟 property graph 的“节点/边均可带属性”与表格字段映射，但不照搬 OpenCTI/Aleph 的证据、本体和推断体系。

## 4. 关系语义

- 群列表：查询账号 → 群成员/加入群 → 群；查询人角色属于关系，群名称/人数/活跃时间/简介属于群实体 Claim。
- 好友列表：查询账号 → 好友 → 好友账号；分组和好友备注属于关系 Claim，昵称属于好友账号 Claim。
- QQ同机：原号码QQ → 同机 → 关联QQ；相似度和同机证据属于关系，昵称/注册地/账号状态属于目标 QQ。
- 手机绑定QQ：QQ → 绑定手机号 → 手机；手机号类型和绑定时间属于关系，不应默认写成手机全局属性。

## 5. 导入体验

新增“智能表格导入”，现有简单批量导入保留：

1. 粘贴或选择 CSV/XLSX。
2. 根据表头、列数、样例类型和空值率识别模板。
3. 显示来源对象、目标对象、关系、对象属性、关系属性和忽略列。
4. 预览有效行、缺主键、重复、预计新增/复用对象、关系和属性。
5. 展示几行原表值与将要生成的节点/关系预览。
6. 用户确认一次，原子写入 Entity/Relation→结构化属性→Batch。
7. 结果可按批次回滚。

## 6. 实施顺序

- P0：对象属性表、关系属性表、字段字典；群列表/好友列表模板；粘贴识别、映射预览和批次回滚。
- P1：QQ同机、手机号绑定QQ；节点/关系属性检查器；案件包v3。
- P2：直接录入的可选结构化字段、模板版本和字段别名管理。
