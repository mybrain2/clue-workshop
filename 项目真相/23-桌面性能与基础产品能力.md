# 桌面性能与基础产品能力

## 为什么桌面版此前看起来比 HTML 慢 / 差

不是桌面容器天生性能差，而是此前桌面版有三个实现问题：

1. **基线没迁移完整**：网页已有成熟画布逻辑，桌面版却先用了新的固定示意，造成操作链和视觉质量倒退。
2. **全页状态耦合**：案件切换、对象选择、关系编辑容易触发整个工作区重渲，桌面 WebView 对这种无效刷新更敏感。
3. **没有大图降载策略**：原网页已形成“阅读优先 / 局部关系 / 聚合”方向，桌面版未继承。

结论：桌面版必须比 HTML 多出 SQLite、文件、备份和系统能力，但前端体验必须以网页工作流为基线；不能重新做一套较弱的画布。

## 本轮优化

### 画布性能

- `GraphPanel` 使用 memo 化，案件细节、视图、选中对象、两跳深度变化之外不重算图投影。
- 关系图投影按当前视图局部化：主体关系默认一跳，二跳按需展开。
- 当前画布设默认渲染阈值为 36 个节点；超过时优先保留根节点和高优先对象，提示用户通过全量表或重新聚焦继续查，避免一次把数百节点塞进 SVG。
- SVG 交互只更新缩放和平移 transform；滚轮缩放、空白拖动不访问 SQLite、不触发案件列表刷新。
- 阅读 / 总览直接重置局部视图状态；不重建案件数据。

### 工作台基础能力

- **案件搜索**：左下角搜索框可按案件名、归档名、背景过滤。
- **命令面板**：`⌘/Ctrl + K` 打开，可新建案件、切换案件、为当前对象添加关联、编辑当前对象、导出简报。
- **快捷键**：
  - `⌘/Ctrl + K`：命令面板；
  - `A`：为当前对象添加关联；
  - `E`：编辑当前对象；
  - `Esc`：关闭命令面板并清空搜索。
- **状态反馈**：顶部统一显示本地数据库、保存、导出和错误状态。
- **上下文约束**：主工作区不永久展示所有动作；当前对象存在时才开放录入和编辑动作。

## 顶级产品经理的结构判断

### 必须继续做的基础能力

1. 操作历史 / 撤销重做与快照恢复；
2. 高连接分支的真实聚合节点与分页展开，不只是阈值裁切；
3. 画布视图状态按案件保存：缩放、平移、展开分支、当前节点；
4. 全局搜索扩展到节点、关系和备注，并点击定位到图；
5. 案件空状态、导入空状态、数据库故障状态；
6. 导出中心：快照版本、概括、SVG/PNG、CSV/XLSX、casepack；
7. 备份健康提示与恢复演练。

### 不应过早做的

- 外部数据接入；
- 多人同步；
- AI 自动认定 / 自动结论；
- 全案无限网络图默认视图。
