# 42 - AI 协作与工程验收

## 目的

本文件规定后续 AI 修改“线索研判”时的工作方式。目标不是尽快生成一次改动，而是避免“代码已经改了，运行版没有变”“说明文档领先于真实交付”“只修截图局部、破坏全局交互”等重复问题。

## 工作原则

1. **先读当前事实，再写代码**：先读 `00-AI接手总览.md`、目标模块、相关类型、后端入口和现有验证脚本。不得根据旧版本描述猜实现。
2. **先确认可复现现象**：视觉或交互反馈需要截图、实际窗口或自动化浏览器复现；CSS 必须读取最终 `getComputedStyle`，不能只看源码规则。
3. **改动从数据边界向 UI 走**：涉及实体、关系、归档、导入导出时，先确认 `case_core.rs` 的快照、去重、revision 和 CLI/MCP 是否同步。
4. **小步、可验证**：每个功能模块完成立即构建和验证；同一个问题连续三次无根因修复，应停止猜测并说明证据与阻塞。
5. **恢复优先于重做**：用户要求“加回来”时先找此前语义和行为，不要借机再设计一套不兼容流程。
6. **文档只写已确认事实**：未验证项标为风险或待验收；不要用“已完成”替代实机检查。

### 视觉或交互改动的额外验证

1. 启动真实 Tauri App 或开发版。
2. 针对用户报告的动作亲自触发一次：点击、拖动、滚轮、键盘删除、导入等。

## 画布特殊规则

- React `onWheel` 不足以保证 WebKit 阻止原生滚动；使用 canvas 原生 `addEventListener('wheel', handler, { passive:false })`，清理监听器。
- SVG 中缩放与平移必须在同一个状态对象内更新；锚点纳入 `scrollLeft`/`scrollTop`。
- 不能在条件 `return` 后添加 Hook；案件从空状态切换为有数据时会破坏 Hook 顺序并白屏。
- 选中语义：节点 -> 一跳节点和边；关系 -> 两端和该边。附属位置/机房卡随来源节点参与高亮，不作为独立主线。
- 普通节点点击必须调用 `onSelect`；节点只有按住 Option（⌥）再拖动才进入有限纵向微调。改这些事件后必须同时复测“点击能选中”和“⌥ 拖动可微调”。
- 不允许为聚焦而降低其他节点/连线透明度；只允许高亮选中对象与直接关联对象。
- 根节点错误边界在 `src/main.tsx`；不要移除，它是渲染异常时不白屏的兜底。

## CSS 特殊规则

- 样式文件目前存在历史规则叠加；新增覆盖必须检查选择器优先级和加载顺序。
- 调整右侧快捷录入时，以 `.desktop-app .inspector ...` 作用域确保最终命中，之后用浏览器读取 `fontSize`、`minHeight`、`padding`。
- 设计目标是本地专业工具，不是营销后台：低饱和、紧凑、文本优先、关键动作明显。

## 发布流程

1. 将 `package.json` 和 `src-tauri/tauri.conf.json` 版本一起更新。
2. 运行 Tauri build、两条回归。
3. 从本次构建的 `src-tauri/target/release/bundle/macos/线索研判.app` 复制到 `release/macOS/线索研判-<version>.app`；发布目录只保留当前版本。
4. 复制本次 CLI 与 MCP 配置，重新生成 MCP JSON 的绝对路径；给外部机器时用占位路径并说明替换。
5. 临时签名、严格验证、创建并验证 DMG。
6. 将 `新电脑安装与AI部署说明.md` 与操作海报复制到发布目录；不得放入源码、项目真相或任何案件数据。
7. 启动发布 App、核对日志和 CLI SHA-256 一致性。
8. 只在以上步骤都通过时展示交付。

## 文档义务

一次实质改动完成后：

- 更新 `00-AI接手总览.md`（仅当前事实改变时）。
- 更新受影响的核心事实文档与 `CHANGELOG.md`。
- 在 `项目真相/` 记录本次设计与验证证据。
- 更新根目录 `overview.md`，使产物面板展示当前阶段。
- 追加 `.workbuddy/memory/YYYY-MM-DD.md`。

## 不可做

- 不直接改用户数据目录中的 SQLite 以伪造测试结果。
- 不因为演示方便创建未清理的真实案件测试数据；测试完成后移入回收站或使用隔离样本。
- 不输出“应该可以”“已修复”而没有构建和实际界面证据。
- 不把安全、导入、导出和撤销的未完成能力写成已支持。
