# 懒人录入与滚动边界修复

> 版本：0.6.1。状态：已完成实现、构建和发布版验证。

## 问题定位

### 1. 节点重复显示账号

节点第一行已经显示 `QQ号 · 主值`；第二行在没有账号命名或备注时又回退显示主值，因此视觉上形成重复账号。修复后：

- 永远保留第一行 `类型 · 主值`；
- 第二行只在有人工命名时显示命名；
- 没命名但有备注时显示“有备注”；
- 两者都没有时第二行留空，不重复主值。

### 2. 新建案件体验

原“＋”只有图标、命中范围小，且新建表单把背景、对象类型、初始值同时铺开；`autoFocus` 与模态层/浏览器焦点竞争会让输入看起来跳到其他元素。

修复后：

- 按钮改为 `＋ 新建`，有明确文字反馈；
- 打开时状态栏立即显示“输入案件名和第一条线索即可”；
- 表单只保留案件名称、第一条线索两个必填项；
- 第一条线索自动尝试识别微信、QQ、手机号、IP；人工类型选择只保留为四个轻量按钮；
- 案情简介收进“补充案情简介（可选）”；
- 使用受控 ref 延迟聚焦案件名称，不再依赖多个 `autoFocus`。

### 3. 新建顺序

创建时原逻辑为 `MAX(sort_order)+1`，侧栏按升序显示，故新案件在底部。现改为 `MIN(sort_order)-1`，新案件默认置顶；拖拽排序逻辑保持不变。

### 4. 滚轮边界

窗口/画布的滚轮监听导致用户难以判断哪里是滚动、哪里是缩放。现规则：

- 左侧案件库、右侧检查器：各自独立纵向滚动；
- 中间关系画布：仅画布区域拦截滚轮做缩放；
- 画布以外区域不 `preventDefault`，不会影响侧栏滚动；
- 工作区采用 `100vh` 与独立 overflow，避免全窗口和侧栏争夺滚动。

## 最少点击原则

参考渐进披露与快捷输入范式，不再让“添加线索”先经过类型、关系名称、扩散方式、备注四层输入：

1. 选中当前对象；
2. 点击 `＋ 添加线索`；
3. 直接粘贴一个或多条值；
4. 自动识别常见类型、去重并显示数量；
5. 确认即可写入。

关系名称、扩散方式、备注、自定义类型全部收进“关系与说明（可选）”。批量导入继续保留在旁边，供 Excel/截图使用。
