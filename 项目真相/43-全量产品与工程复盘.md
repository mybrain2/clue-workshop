# 43 - 全量产品与工程复盘

> 复盘基于 0.7.9 源码、现有回归脚本、发布检查和多轮真实窗口反馈。结论分为已具备、已验证缺口、建议，不把建议伪装成缺陷。

## 结论摘要

产品已完成从网页演示到本地桌面案件工作台的关键跃迁：真实 SQLite 图数据、案件隔离、快捷录入、三种图表视图、基本恢复、案件包交换和受控自动化形成闭环。当前最大风险不在“再加一种节点”，而在**真实案件数据的导入可控性、证据与附件治理、图谱阅读稳定性、文档与测试的单一事实源**。

正式定位应为：**已可内部试用的本地优先线索关系工作台，不应宣称为生产级 P0。**

## 一、产品能力审计

### 已形成闭环

| 链路 | 状态 | 依据 |
| --- | --- | --- |
| 新建案件 -> 首条线索 -> 图谱 | 已实现 | `create_case`、CreateCaseDialog、GraphPanel |
| 选节点 -> 快捷关联 -> 多值去重写入 | 已实现 | QuickAddDialog、`add_relations` |
| 图数据 -> 调查路径/局部网络/表格 | 已实现 | GraphPanel 三视图投影 |
| 变更 -> 撤销/重做 | 已实现 | case snapshots/redos、CLI 回归 |
| 材料导出 -> 案件包导入新案件 | 已实现 | `export_case_to`、`import_case_package` |
| 人工界面 <-> CLI/MCP 同库同步 | 已实现 | revision polling、CLI/MCP 回归 |
| 归档/文件夹/回收站 | 已实现 | `archive_folder`、CaseSidebar |

### 仍有功能缺口

| 优先级 | 项目 | 为什么重要 | 建议验收 |
| --- | --- | --- | --- |
| P0 | 导入批次审计与回滚 | 当前 Excel/文本导入一旦确认即写入，难以理解“本次导入造成了什么” | 每次导入生成 batchId、数量、源文件摘要；可仅回滚该批次 |
| P0 | 附件归档与关联 | 目前有 attachments 目录但没有附件对象、哈希、关联关系或可见入口 | 能导入附件、记录 SHA-256/原名/时间、关联案件或节点，不删除源文件 |
| P0 | 真实案件可读性验收 | 90/89 样本只能证明结构正确，不能证明调查阅读正确 | 用脱敏真实案件完成任务观察：录入、定位主链、导出、恢复 |
| P1 | CSV/Excel 导出一致性 | 已有 CSV，但用户常需要结构化表格交接 | 定义字段、编码、列顺序、版本；导出并由外部表格工具读回 |
| P1 | 关系筛选与搜索 | 图大后只有聚合不够，需要按类型、状态、重点、对象值定位 | 筛选不改变原始数据，清楚显示激活条件 |
| P1 | 案件包版本兼容策略 | package 有 version，但兼容规则未形成合同 | 导入旧版、未知字段、缺字段必须可预测地拒绝或迁移 |
| P2 | 跨案关联 | 有价值但会破坏“案件是隔离边界” | 独立索引与显式跨案视图，不直接合并节点 |

## 二、交互与视觉审计

### 已改善点

- 主线、附属位置/机房、聚合分支已形成不同层级。
- 右侧高频录入已覆盖常用对象类型；低频字段渐进展开。
- 节点和关系的状态、重点、排除、失效已表达在图上。
- 选中节点/关系的局部高亮已恢复，用户能确认当前正在查看哪条路径。

### 仍需重点治理

1. **缩放与平移没有完成真实高频手感验收**
   - 0.7.7 已改为非被动原生 wheel 监听并通过计算/启动验证，但必须由用户在长图、横向滚动、连续滚轮条件下确认。
   - 后续不要再靠公式推导宣称交互完成；需要录制或脚本触发并比对鼠标锚点。

2. **右侧快捷卡仍有“功能很多、视觉弱层级”的风险**
   - 当前 11 类动作在窄栏中同时出现，虽然已收紧，但选择成本仍高。
   - 建议 P1 以“账号 / 网络 / 群组与组织 / 背景信息”四个可折叠小组组织，保持一键输入，不再重新引入二次类型选择。

3. **关系点击与节点点击语义必须持续一致**
   - 节点选中：突出一跳边和关联节点。
   - 关系选中：突出该边和两端；编辑弹窗不应让高亮消失。
   - 不建议全局灰化其余图，会损失上下文。

4. **状态表达需要统一到侧栏、表格和导出**
   - 当前画布表达最完整；后续筛选、表格行状态、简报口径要和画布一致。

## 三、数据、安全与可靠性审计

### 当前优势

- 数据默认本地保存，无网络服务和账号体系。
- SQLite 使用参数绑定，外部输入通过 Tauri 命令/CLI 输入结构进入核心。
- 永久删除需要案件标题确认，CLI/MCP 不暴露永久删除。
- 导出案件包可导入为新案件，不直接覆盖现有案件。

### 风险与建议

| 优先级 | 风险 | 建议 |
| --- | --- | --- |
| P0 | 本地数据库、导出包和附件均未加密 | 先做用户可理解的备份/恢复，再评估平台钥匙串派生密钥或加密容器；不能把“有本地目录”说成“安全存储” |
| P0 | 缺少附件对象模型和文件完整性验证 | 附件表 + SHA-256 + MIME/大小白名单 + 删除策略 |
| P1 | OCR 临时文件依赖外部 helper | 明确 helper 版本、失败提示、清理保障和敏感图像留存策略 |
| P1 | 运行日志可暴露操作痕迹 | 日志避免写入线索原值；提供可控日志级别和清理说明 |
| P1 | 导入缺乏来源元数据 | 记录导入时间、文件摘要、用户映射、批次 ID，不把原文件强制复制到数据库 |

## 四、工程与可维护性审计

### 已有基础

- React feature 目录与 Rust `case_core` 核心已分开。
- Tauri、CLI、MCP 共用核心逻辑，减少多套数据规则。
- Rust release 使用 LTO、strip 和 size 优化。
- 有多跳回归、CLI/MCP 闭环回归、构建、签名和 DMG 校验。

### 债务

1. **App.tsx 过于压缩且职责过多**：案件加载、快捷键、对话框、导入导出、右侧面板都在一个文件。建议拆为 WorkbenchShell、Inspector、KeyboardShortcuts 和 dialog coordinator；先补组件边界测试再拆。
2. **app.css 是历史规则累积**：已出现后定义规则覆盖前面规则的真实事故。建议把基础 token、layout、graph、inspector、dialog 分文件或至少分层；加入计算样式的视觉回归。
3. **case_core.rs 同时承担 schema、迁移、领域操作和导出**：当前体量尚可，但附件、导入批次和版本迁移加入后必须拆为 storage/schema、case_service、package_service。
4. **测试集中在脚本式回归**：缺少 UI 交互回归、失败路径与导入包兼容测试。优先补“缩放锚点、节点/关系高亮、归档文件夹、案件包导入”的浏览器/桌面冒烟。
5. **发布流程尚是人工命令串**：应沉淀为受控发布脚本或 CI，但在引入前必须保证不自动操作用户数据目录。

## 五、建议路线图

### 下一迭代：可用性与数据可追溯（P0）

1. 导入批次模型、导入记录、单批次回滚。
2. 附件模型、哈希、案件/节点关联、可见列表。
3. 使用一份脱敏真实案件完成 5 个任务的人工验收：建案、批量导入、定位关联、标状态、导出/导入。
4. 图谱互动实测：缩放、选中高亮、拖动、折叠分支，形成截图/录屏基线。

### 第二迭代：检索与交接（P1）

1. 图内搜索、类型/状态/重点筛选与清晰的筛选反馈。
2. 统一 CSV/XLSX 输出合同，增加输出内容自检。
3. 案件包版本兼容和导入失败的可读诊断。
4. App.tsx/CSS 拆分，加入 UI 冒烟。

### 后续探索（P2）

跨案关联、时间线、地图、协作与加密必须以真实工作流和安全模型为前提，不建议为“功能丰富”提前实现。
