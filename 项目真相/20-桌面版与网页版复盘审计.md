# 桌面版与网页版复盘审计

> 结论：桌面版不是“网页版迁移版”，而是“桌面壳 + 案件库 + SQLite 骨架”。将它作为原产品的桌面版本交付是不准确的。

## 1. 复盘结论

### 原本应该做什么

把已经验证过的网页工作台完整迁移到桌面容器：

```text
相同的案件操作路径
+ 相同的关系录入与图谱阅读能力
+ 相同的节点/关系语义
+ SQLite 本地存储、归档、回收站、备份和导出
```

### 实际做了什么

桌面版优先完成了：

```text
Tauri 应用壳
+ SQLite 建表与案例列表
+ 右键归档 / 回收站 / 手动永久删除
+ 固定示意图
+ 基础文本/SVG/CSV 导出
```

这导致中间的核心调查工作台被替换成了静态示意画面，而不是迁移。

### 直接责任

我把“桌面应用基础设施已可运行”错误表述得过于接近“P0 已可用”。事实是基础设施可运行，但核心产品能力没有迁移完成。

## 3. 视觉与体验审计

### 设计连续性：不通过

网页版本形成了明确的产品语义：

```text
左：案件库
中：可操控的真实关系画布
右：当前对象、直接关联、备注、关系链、简报
```

桌面版保留了三栏外形，却把最关键的中间画布和右侧工作区替换成静态占位内容。表面相似，使用逻辑已经断裂。

### 高优先级问题

#### P0：静态图伪装成案件图

- **问题**：`GraphPanel.tsx` 直接写死 `wxid_lyra`、手机号、QQ、IP 和位置节点；画布不读取 SQLite 实体和关系。
- **影响**：用户切换案件后，中间图仍不是该案件的真实图，会产生“数据已保存但界面不可信”的严重问题。
- **整改**：抽取网页的图数据投影、分层布局、节点选择、缩放/平移/拖动、路径/网/表三视图，重写为 React 图谱组件，并只从 SQLite 仓储读取数据。

#### P0：右侧快捷动作是无效 UI

- **问题**：当前“添加手机号 / 添加QQ号 / 添加活跃位置 / 全部关联”没有连接数据命令。
- **影响**：最关键的“少打字、直接填”的主路径消失。
- **整改**：迁移网页中预设对象字典、批量粘贴、去重、扩散方式、备注和自定义关联表单；成功后立即写 SQLite 并更新画布和简报。

#### P0：桌面版没有真实对象与关系编辑

- **问题**：节点/关系状态、角色、重点色、备注、推导说明在数据库表结构和 UI 命令中未完整闭环。
- **影响**：案件不能沉淀“怎么推出来的”，也无法复盘。
- **整改**：新增实体详情抽屉和关系详情抽屉；复用网页字段模型，加入 SQLite migration 和操作历史。

#### P0：导出不能代表案件真实结构

- **问题**：当前 SVG 是固定示意图，文字概括主要按数量模板生成。
- **影响**：用户要求的“概括 + 脑图”没有达成。
- **整改**：导出必须由同一份案件快照生成：`summary.md`、真实图谱 SVG/PNG、全量表 CSV/XLSX、`casepack`。导出前创建快照，四个产物携带同一 snapshot id。

#### P1：新建案件缺少起点

- **问题**：网页在新建时强制案件背景 + 起点类型 + 起点值，桌面版只收案件名和背景。
- **影响**：破坏“从种子线索向外查”的工作模型。
- **整改**：迁移原新建案件流程；创建事务内同时写 case、主体簇、种子实体和“初始线索”关系。

#### P1：视觉没有沿用网页的可读性策略

- **问题**：桌面版有模仿性的三栏和色调，但没有实体层级、关系弱化、选择态、画布控制、标签碰撞避让、聚合及阅读/总览逻辑。
- **影响**：它看起来像新做的仪表板，不像已经打磨过的案件工作台。
- **整改**：先复用网页版的布局与视觉 token，再逐步把 CSS/SVG 绘制拆成 React 组件。不能重新发明一套桌面视觉。

## 4. 产品体验评分

按已加载的可用性审查规则，对当前桌面版评分：

| 维度 | 评分（0-4） | 结论 |
|---|---:|---|
| 系统状态可见性 | 2 | 有“本地数据库已就绪”，但案件图不反映真实状态 |
| 与真实工作流匹配 | 1 | 缺少“选关系→填结果→立即成图”的主链 |
| 用户控制与自由 | 2 | 归档/回收站较好，图谱操作缺失 |
| 一致性 | 1 | 与已验证网页交互不一致 |
| 错误预防 | 2 | 永久删除确认存在，录入验证不存在 |
| 识别而非回忆 | 1 | 关键关系字典和当前对象上下文缺失 |
| 效率与灵活性 | 1 | 没有快捷录入、批量粘贴、撤销重做 |
| 审美与极简 | 2 | 外壳克制，但静态示意破坏可信度 |
| 错误恢复 | 1 | 存储层有基础，操作层无撤销/恢复快照入口 |
| 帮助与引导 | 1 | 无首要路径引导 |
| **合计** | **14/40** | 当前只能视为基础壳，不可作为可用 P0 |

认知负担检查失败 5 项：单一焦点、工作分块、可见选择、工作记忆、渐进披露。根因不是内容太多，而是核心编辑动作不在当前上下文内。

## 5. 重新定义桌面版迁移合同

### 不允许缩水的基线

桌面版下一版必须至少与网页当前功能等价：

1. 同一案件数据生成真实路径、关系网、全量表；
2. 节点选择后出现完整快捷关联和自定义关联；
3. 单条/批量录入，自动去重，自动连图；
4. 节点和关系的状态、角色、备注、扩散方式、推导说明、重点标记；
5. 路径阅读、关系网、表格、缩放、平移、节点拖动、阅读/总览、聚合展开；
6. 撤销/重做；
7. 基于真实案件快照的概括、脑图和全量关系导出。

### 桌面版才新增的能力

这些能力叠加在等价功能之上，不能替代等价功能：

- SQLite 与独立数据目录；
- 案件右键菜单、拖拽排序、可命名归档；
- 不自动清理的回收站、手动永久删除；
- 快照、备份、恢复、案件包；
- 原生文件导出、桌面安装和后续签名更新。

## 6. 整改顺序

### 第 1 阶段：恢复核心工作台（必须先完成）

- 用 React 迁移网页图数据模型和画布投影；
- 迁移三栏信息架构及右侧当前对象面板；
- 接上 SQLite entities / relations，不再写死图节点；
- 迁移新建案件的种子线索、快捷关联、批量粘贴、自动去重和实时刷新。

**验收**：同一份样例数据在网页和桌面端显示相同的对象数量、关系数量、路径结构和快捷关联入口。

### 第 2 阶段：恢复语义和操作安全

- 迁移实体/关系详情编辑、状态、角色、备注、颜色、重点、扩散方式；
- SQLite 增加对应字段、关系唯一 ID、历史操作与事务；
- 迁移撤销/重做、自动保存和快照。

**验收**：在任一端改对象或关系后，桌面端重启仍保留；操作历史可证明本次修改。

### 第 3 阶段：恢复真实导出

- 从同一快照生成概括、路径脑图 SVG/PNG、全量表 CSV/XLSX、案件包；
- 不允许固定示意 SVG；
- 脑图可独立打开，打印与缩放可读。

**验收**：导出的对象数、关系数和简报内容与当前案件快照完全一致。

### 第 4 阶段：补桌面增强能力

- 右键归档、回收站、排序、备份、恢复、应用设置、签名更新；
- 这些能力在前 3 阶段可并行开发，但不能以此替代主工作台。

## 7. 立即纠正的承诺

后续不再把桌面版称为“已完成 P0”或“原功能已迁移”，直到上述 7 项基线全部完成并经过逐项验证。

当前桌面代码保留价值只有两部分：**正式 Tauri 应用壳**和**独立 SQLite / 案件管理基础设施**。中间工作台要以网页版本为源，做真实迁移，而不是在静态样例上继续堆功能。
