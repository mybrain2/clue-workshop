# Demo 方案：案件线索工作台

## Demo 的目的

Demo 不验证数据接入，不验证多人协作，也不验证全部分析算法。

它只验证一件事：面对“账号 → 多手机号 → 多 QQ/微信 → IP/设备/群聊 → 多主体回连”的真实关系，用户能否**少打字、不断线、看得懂、随时导出当前结论**。

## 候选收敛

| 候选 | 角色 | 结论 | 原因 |
|---|---|---|---|
| AntV G6 v5 | 主画布 | 采用 | 同一图模型可承载调查路径、主体关系网、聚合节点和布局切换；MIT。 |
| Mind Elixir | 脑图导出/增强 | Demo 不接入 | 树编辑能力强，但不能作为多对多关系的权威画布；先避免双画布与双状态。 |
| Cytoscape.js | 高密度关系网备选 | Demo 不接入 | 网络分析能力强，但 G6 先做 PoC；避免两套图形引擎。 |
| React Flow | 不采用 | 排除 | 更像流程图编辑器，会诱导手动拉线和排版。 |
| Casebook | 产品结构参考 | 不 fork | 案件/导出思路有价值，但其既有工作流不适合极简录入。 |
| Flowsint | 图谱交互参考 | 不 fork | 关系探索可参考，但产品目标不是通用 OSINT 工作台。 |
| Impeccable | 产品设计约束 | 已采用 | 用于信息架构、低认知负担、状态设计与视觉质量控制。 |

## Demo 范围

### 1. 案件库

- 展示 3 个样例案件；
- 新建案件：只填名称、背景、首条线索；
- 切换案件：恢复该案件的图、当前视图、选择节点和展开状态；
- Demo 采用浏览器本地持久化，刷新后保留；不模拟服务器协作。

### 2. 当前案件工作台

工作台不拆多页，保持一个核心画布：

```text
顶部：案件切换 / 视图切换 / 导出简报
左侧：当前节点与“下一枝”快捷操作
中部：G6 画布
右侧：实时简报与当前分支摘要
底部：批量粘贴结果抽屉（按需打开）
```

### 3. 三种视图

- **调查路径**：默认。以当前种子或主体簇为根，树形展示，只展开当前需要看的分支。
- **主体关系网**：查看同 IP、同机、共同群、跨主体回连，支持一跳/两跳过滤。
- **全量表**：从图自动生成，按对象、关系、关联对象、数量、展开状态展示。

### 4. 快速录入

选中节点后，显示不超过四个高频下一枝；其余放入“更多”。

例如选中微信：

```text
[关联手机号] [关联 QQ] [登录 IP] [群聊]
```

点击后输入单值或粘贴多行：

```text
13800138000
13900139000
13700137000
```

系统应：

1. 预览“将添加 3 个手机号”；
2. 去除重复值；
3. 创建或复用节点；
4. 建立关系；
5. 更新聚合数、图、表和简报；
6. 支持撤销。

### 5. 聚合与回连

- 18 个同 IP 账号默认显示为 `同 IP 账号（18）`；点击后展开；
- 56 个群成员默认显示为 `群成员（56）`；只加载当前展开的部分；
- 已存在的账号出现在另一条路径中时，显示引用/回连，而非复制实体；
- 两个主体簇共享 IP、设备或群聊时，在关系网中显示弱连接，在调查路径中不强行合并。

### 6. 自动简报

点击“生成简报”或每次变更后实时更新预览：

```markdown
## 起点与主链
## 账号画像
## 社交扩展
## 核心节点
## 待展开分支
```

Demo 采用规则模板生成，不使用模型编造未录入内容。

## Demo 样例案件

### 案件 A：跨平台账号链

```text
初始微信 wxid_lyra
→ 手机号 13800138000、13900139000
→ 13800138000 关联 QQ 123、QQ 456、微信 wxid_nova
→ QQ 123 与 wxid_nova 同机 Device-A1
→ QQ 123 登录 IP 10.2.3.4
→ IP 10.2.3.4 关联账号（18）
→ QQ 456 加入群 8899
→ 群 8899 成员（56），其中 3 个可扩展为新主体簇
```

这个案例必须验证：一对多、跨平台、同机、同 IP 聚合、群聊多主体和回连。

### 案件 B：群聊起点

从群 7722 开始，先展开成员，再选择成员建立主体簇，验证“群聊是关系中心而非账号附属字段”。

### 案件 C：设备起点

从 Device-B2 开始，展开同机账号和共同群，验证非账号种子也能形成调查路径。

## Demo 技术边界

```text
React + TypeScript + Vite
AntV G6 v5
Zustand 或轻量状态层
IndexedDB / localStorage（Demo 持久化）
规则模板简报
```

不引入：Neo4j、PostgreSQL、Cytoscape.js、Mind Elixir、后端 API、模型服务。

这是刻意取舍：先验证操作路径与画布语义，再升级长期存储与服务端。

## Demo 验收标准

1. 三个案件可创建、切换、刷新后恢复。
2. 从任意节点新增一条关系不超过 3 秒。
3. 粘贴 20 条同类结果，一次预览后写入，不产生重复节点。
4. “手机号 → 9 个 QQ”“群聊 → 56 个成员”“IP → 18 个账号”默认聚合，不导致画布不可读。
5. 同一个账号被不同路径命中时只有一个实体节点。
6. 调查路径、关系网、全量表展示的是同一份数据。
7. 每次修改后简报内容同步更新，且不新增未录入事实。
8. 新增、删除关系支持撤销/重做。

## Demo 后的决策门

以下全部通过，才进入 P0 正式实现：

- 用户认为它比现有 Excel 少打字、少重复、容易回看；
- 树模式与网模式的切换不造成理解断层；
- 聚合节点可以控制复杂度而不隐藏重要路径；
- 案件切换和本地恢复足够稳定；
- G6 的渲染、交互和布局在样例规模下流畅。

如果失败，先调整交互和画布方案，不急着接后端或增加功能。
