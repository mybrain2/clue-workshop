# 98 - 20260923 绑定手机号方向合同v2与未连接根因修复

## 背景

用户截图质疑：手机号查出来的QQ为什么箭头"往回走"、且出现在"未连接对象"区域。

排查结论分两层：

1. **视觉层**：布局从主体沿箭头BFS分层。绑定QQ只有出边无入边（QQ→绑定→手机号），从根不可达，被归入"未连接"甩到最右列，箭头逆流指向左侧的手机号。
2. **语义层（真正的根因）**：六模板中五个方向都是"查询起点→结果"顺流（查询QQ→加入群→群、查询账号→好友→好友QQ、原QQ→同机→同机QQ、群→成员→QQ、QQ→手机号→手机）。唯独 `qq-phone-binding` 当时按"事实方向"定成 QQ→绑定→手机号，起点却是手机号——查询出来的QQ成了关系上游，天生无入边。

用户设计判定：**"手机号查出来的QQ应该也是顺的，跟手动添加关联线索一个道理"**。确认方向合同错误，五个模板统一的"起点→结果"规则才是正确合同，"事实方向"论证被否决。

## 方向合同 v2

全部六模板统一：**关系方向 = 查询方向（起点 → 结果）**。

| 模板 | 起点 | 关系方向 |
|---|---|---|
| 群列表 | 查询QQ | QQ→加入群→群 |
| 好友列表 | 查询账号 | QQ→好友→QQ |
| 同机QQ | 原QQ | QQ→同机→QQ |
| 群成员 | 群 | 群→成员→QQ |
| QQ查手机号 | QQ | QQ→手机号→手机 |
| **手机号查绑定QQ** | **手机号** | **手机号→绑定手机号→QQ**（本次翻转） |

翻转让查询结果QQ自然挂在手机号下游、箭头顺流向右，与手动添加关联线索完全同构；同时消灭了该模板天生的"结果无入边"问题——手机号作为起点必有入边（桥接/复用时），QQ作为其结果从根沿箭头可达，不再进入未连接区。

事实表达不受损：该手机号被哪些QQ绑定，语义为"手机号 →绑定→ 这些QQ"，读作"这个号码查出来的绑定QQ"。两张表（QQ查手机号 / 手机号查QQ）分别从各自起点出发，同一对账号双向都查时会形成两条不同方向的边，属预期（各自查询路径的表达）。
