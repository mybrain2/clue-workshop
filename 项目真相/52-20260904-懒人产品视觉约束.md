# 52 - 2026-09-04 懒人产品视觉约束

> 本文是后续所有 UI、图谱、XMind 视觉变更的上位约束。优先级高于“看起来更丰富”的主观设计冲动。

## 1. 产品判断

线索研判是本地优先的懒人工作台，不是专业分析平台的完整复刻，也不是视觉作品集。

用户应该在不学习复杂规则的情况下完成：新建案件 → 添加线索 → 看清主链 → 标记重点 → 导出/带走。

## 2. 视觉目标

- 克制：一屏只有一个阅读重点，不用装饰填满空间。
- 高级：依赖排版、比例、留白、材质层级与一致状态，而不是渐变、炫彩、虚线或复杂图标。
- 快速：默认看见主链和关键对象；次要信息按需出现。
- 稳定：视觉变更只作用于呈现层，不能改变关系、对象类型、选中、拖动、导出和数据写入逻辑。

## 3. 不做什么

- 不新增常驻复杂工具栏、图层面板、算法菜单或专家级配置。
- 不为“高级感”加入渐变、彩虹配色、网格装饰、菱形/粒子装饰、厚重阴影。
- 不让每条关系、每个类型、每项状态同时抢占颜色和标签。
- 不把完整证据、备注、来源塞进节点正面。
- 不修改用户已认可的重点表达，除非明确提出并先通过设计评审。

## 4. 最小视觉语法

- 一个对象：一张紧凑卡片；主名称 + 一行辅助信息。
- 一条关系：一根线；默认只有方向，名称在选中或阅读路径中显示。
- 一个状态：一个小、稳定、可读的标记；颜色不是唯一含义。
- 一个重点：保留琥珀外圈与角标。
- 一个附标签：作为主节点的从属信息，不作为竞争对象。

## 5. 实施门槛

每次视觉改动按以下顺序：

1. 仅用静态 mock 说明变化；
2. 用户确认后才修改代码；
3. 每次只修改一个视图或一个组件；
4. 构建、真机截图、关键交互回归；
5. 更新 `项目真相/` 并打开预览。

未满足以上门槛，不得替换桌面发布包。
