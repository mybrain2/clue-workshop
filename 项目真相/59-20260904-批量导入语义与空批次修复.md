# 59 - 2026-09-04 批量导入语义与空批次修复

## 1. 用户现象与根因

截图显示：第一次导入 18 个 QQ 候选时实际新增 18 条关系；随后重复点击导入产生多条“新增 0 条”的最近批次。图谱对大分支默认折叠，导致用户误以为导入没有真正形成。

此前后端即使实际新增为 0，也会记录空批次；前端又统一显示“已创建批次”，使“全部重复”看起来像一次成功写入。

## 2. 对象类型与扩散方式

- 对象类型回答“这一批值是什么”：例如 QQ 号码选 QQ号、手机号选手机号、IP 选 IP。
- 扩散方式只记录“这些关系是通过什么方式得到的”，不改变对象类型，也不会触发外部自动查询。
- 推荐默认：
  - 微信、QQ、手机号、平台账号：账号链扩展
  - IP：同 IP 扩散
  - 设备：同机扩散
  - 群聊：群聊扩散
  - 位置、机房、组织、自定义：人工关联
- 用户手工修改扩散方式后，切换对象类型不会覆盖该选择。
- 主体簇不再作为批量导入目标。

## 3. 修复

- 导入结果改为结构化统计：候选数量、实际新增关系数、跳过/已存在数量、可选批次。
- 实际新增为 0 时不创建 `import_batches`、关系/实体映射、历史或操作记录。
- 前端 M=0 时显示“没有新增，候选均已存在”，不再显示“已创建批次”。
- 有新增时提示：新增 M、已存在/跳过 N-M；若大分支会折叠，明确提示点击图谱“展开 N 项”。
- 对象类型和扩散方式增加短说明；关系名称仍随类型预置但可手改。
- 保持提交按钮 busy 防重复，成功后刷新案件和最近批次。
