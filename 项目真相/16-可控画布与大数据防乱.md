# 可控画布与大数据防乱

## 触发反馈

用户提供的两张截图验证了上一版的基础缺陷：

- 调查路径把全部分支塞进固定高度，根节点、卡片和关系标签会互相压住；
- 主体关系图把一跳、两跳和交叉线同时绘制，视觉上像断开的斜线，无法判断当前主线；
- 没有缩放、平移、拖动和适配视图，关系变多后无法主动整理；
- 没有“重点对象 / 重点关系”的视觉入口。

这不是微调间距能解决的问题，改为可操控画布与渐进展示。

## 已实现

### 1. 调查路径

- 采用从左至右的有向层级布局；层间距固定为 232px，节点最低纵向间距为 82px。
- 画布高度可按最大分支自动增长，不再把大量节点压进固定可视区；超出区域用画布平移和缩放查看。
- 关系使用带箭头的明显直线，标签在线中部。标签以碰撞检测选择上下偏移，避免同一区域互相覆盖。
- 分支中同一关系的叶子节点超过 6 个时，默认显示前 4 个和一个“其余 N 个”聚合节点；点击聚合节点才展开余下结果。

### 2. 主体关系

- 默认只展示当前选中对象的一跳关联，而不是全案关系网。
- 一跳关系采用稳定三列：当前对象 → 直接关联 → 按需展开的两跳延展。
- 两跳默认收起；点击“展开两跳”后，第二层按各自直接父节点在第三列排布，不再与一跳节点混画。
- 点击任意对象后，可围绕该对象重新聚焦。交叉关系不会默认把画面变成全案蛛网。

### 3. 画布操控

- 滚轮缩放，范围 45% 至 240%。
- 空白处拖动平移；节点可直接拖动微调位置。
- 提供缩小、100%、放大、**阅读**和**总览**按钮；阅读优先保持至少 90% 的卡片/标签可读尺寸，总览才允许缩小到完整案情。
- 阅读模式默认把起点定位在视野中部并保留后续层级给用户横向拖动查看，避免为塞进一屏把全图压成电路图。
- 调整后的缩放、平移、节点位置和两跳展开状态跟随案件保存在本地状态中；本轮布局算法升级后会重置旧版手工坐标，防止旧位置污染新布局。

### 4. 重点表达

节点编辑新增：

- 自定义重点颜色；
- “标为重点”开关：卡片使用该颜色的轻填充、左侧色条和加强边框。

关系编辑新增：

- “加粗并突出显示”开关：关系线使用起点节点的重点色、4.4px 加粗线和更强标签边框。

对象类型颜色仍然表达 QQ、微信、手机号、IP、设备、群聊等分类；重点颜色只表达案件内的人工关注，不替代对象类型。

## 操作规则

- **沿主线阅读**：先点“阅读”，起点和当前主链保持在可读大小；需要看后续层级时水平拖动画布。
- **查全案脉络**：只在需要确认整体分支范围时点“总览”；总览允许缩小，不作为日常录入和阅读状态。
- **看一个对象周边**：切到主体关系，默认看一跳；确认需要继续时再展开两跳。
- **节点有重叠风险**：先使用自动布局；个别需要人为强调或让位时，再拖动节点。
- **分支数量很大**：优先保留聚合节点，点开后再看明细；全量关系表始终保留全部记录。

## 验证结果

- JavaScript 语法检查通过。
- 浏览器验证了：路径画布加载、缩放控件、节点/关系重点编辑入口、一跳关系和两跳按需展开，以及“阅读 / 总览”切换。
- 验证结束后关闭浏览器自动化会话并停止临时 HTTP 预览服务；不保留本次任务启动的后台预览进程。

## 当前限制

- Demo 的自动聚合只针对同源、同关系、且下游没有额外关系的叶子节点；正式版需将聚合阈值、展开分页和节点数量指标做成案件级可配置项。
- 手工拖动位置保存于浏览器本地状态，正式 P0 要同步进 IndexedDB / PostgreSQL。
- 关系交叉线目前默认不展示为全案网络；后续可增加“显示交叉线”临时开关，但不能设为默认。
