# 直观线索录入与自适应路径

> 版本：0.6.2。状态：已实现、构建和发布版验证。

## 本轮纠偏

上一轮把“添加线索”压缩得过头：类型和扩散方式被塞进进阶区，虽然点击少，但用户无法一眼判断将以什么语义写入关系。这里改为“**核心语义可见，低频细节收纳**”。

## 添加线索

默认窗口包含：

1. 一块可直接粘贴多行的线索值输入区；
2. 可直接点击的账号类型：微信、QQ、手机、IP、群聊、设备、其他；
3. 可直接点击的拓展方式：账号链、跨平台、同 IP、同机、群聊、人工；
4. 实时文字反馈：将以“关系名 · 拓展方式”添加多少条。

输入值仍会自动猜测常见类型，但类型按钮始终可见、可一键覆盖。关系名称、自定义对象类型、推导说明仍在可选展开区，避免常规路径增加无意义输入。

这恢复了旧版“类型和关系可见”的直观性，同时保留多值粘贴、自动类型建议、去重与少输入。

## 调查路径

问题不是关系太多，而是画布把真实内容强塞进固定 `1200×720` 视口，并把 SVG 高度拉伸/缩放到容器高度。90 实体案例会因此缩成不可读的细线。

修复：

- 画布按实际最深层与最下节点计算 SVG 宽高；
- SVG 保留固有尺寸，画布提供横/纵向滚动，不再压缩节点；
- 路径分栏只渲染实际跳数，缺少自定义名时显示“第 N 跳”；
- 升级本地视图布局版本，旧缩放状态不会继续影响新版阅读；
- “阅读”保持完整节点尺寸，“总览”仍可主动缩放。

发布版截图已显示多跳节点以可读卡片尺寸出现，并有画布滚动条承载后续分支。

## 新建案件流程

现有 `CreateCaseDialog` 不再经过通用弹窗和通用 `submit` 分支：独立表单只接收自身受控状态、在打开后用 ref 聚焦名称输入，提交后只调用 `createCase → refresh(record.id) → close`。这样排除通用表单残留字段/焦点竞争导致的跳转。

## 限制

原生窗口仍未获得 Accessibility 权限，自动化无法在 macOS 里点击每一个表单控件；本轮用独立受控表单、编译、真实数据回归、发布版启动与截图验证覆盖。若要对焦点顺序、键盘 Tab 和按钮点击进行逐控件自动化，需要开启辅助功能权限后再补一次原生交互验收。
