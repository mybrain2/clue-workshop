# 调查路径与主体关系重构

## 重构原因

用户反馈中间的“调查路径”和“主体关系”一塌糊涂，不能继续以自由散点图方式修补。

问题根因：

- 路径图以自由坐标铺开所有节点，分支和回连混在同一空间；
- 关系标签、节点和线条没有稳定的结构秩序；
- 主体关系网一次展示全图，导致高连接关系出现大量交叉线；
- 图的目标没有区分：路径视图应帮助回忆调查过程，关系视图应帮助看某个对象的局部交叉关系。

## 新设计

## 1. 调查路径：分层关系链路板

调查路径不再是力导向或自由散点图，而是严格的左到右分层板：

```text
起点 → 首条线索 → 身份 / 联系方式 → 扩展账号 → 环境 / 社交 → 延展
```

规则：

- 从案件根节点按关系发现方向计算层级；
- 每一层固定一条纵向泳道；
- 节点只出现在自己的层级中；
- 使用水平—垂直—水平的直角折线路径连接层级；
- 关系标签贴在首段水平线上；
- 画布宽度会随深度扩展，使用横向滚动查看完整链路，避免把多层节点硬压缩到一个视口；
- 分支继续向右延展，形成可读的调查过程，而非一团节点。

## 2. 主体关系网：当前对象两跳关系板

主体关系网不再一次显示全案所有对象。默认以当前选中对象为中心：

```text
当前对象 → 直接关联 → 两跳延展
```

规则：

- 当前对象固定在左列中部；
- 直接关联对象在中列垂直排布；
- 两跳延展对象在右列垂直排布；
- 只渲染当前对象及两跳范围内的节点与边；
- 选中对象的一跳关系显示关系标签；
- 继续点击任意对象，关系网随之重新聚焦。

这使“主体关系”成为一个可连续探索的局部工作台，而不是一次性全案关系总览。

## 保留逻辑

- 案件独立、可切换；
- 直接添加手机号 / QQ号 / 微信号 / IP / 群聊的操作路径；
- 节点状态、账号角色、备注；
- 关系状态、扩散方式、推导说明；
- 聚合节点、全量关系表和简报导出。

## 后续验证重点

1. 是否需要为路径板增加“只看当前分支”的过滤；
2. 聚合节点是否要在路径板内支持直接展开；
3. 两跳关系板是否需要提供“一跳 / 两跳”切换；
4. 跨主体回连是否以虚线引用还是以单独的交叉关系列表呈现。
