# Demo 实现与验证

## 已实现

文件：`demo/index.html`

这是一个独立静态页面，不依赖 Obsidian、ClueProbe、后端服务或构建工具。它通过 jsDelivr 加载 AntV G6 v5，浏览器本地存储保存案件状态。

### 已实现功能

- 三个样例案件的案件库、切换和独立图数据。
- 新建案件：名称、背景、初始线索。
- 案件内背景、根节点、节点/关系计数和最近保存状态。
- 调查路径、主体关系网、自动全量表三种视图。
- 当前节点卡片与上下文“下一枝”快捷关系。
- 关系录入弹窗：单值、换行或逗号批量粘贴。
- 当前案件内实体去重、已有节点复用、重复关系跳过。
- 实时简报：起点与主链、账号画像、核心节点、待展开聚合分支。
- 样例中的聚合节点：同 IP 账号（18）、群成员（56）、同机账号（12）。
- 撤销、重做、Markdown 简报导出、明暗主题切换和样例重置。
- 浏览器本地持久化：刷新后保留已修改案件数据。
- 节点语义标注：状态、账号/对象角色、对象备注。
- 关系链语义标注：关系状态、扩散方式、推导/注意事项备注。
- 语义节点卡和明确的快捷延伸按钮：动作 + 目标对象类型 + 扩散方式。

## 当前限制

1. Demo 使用 localStorage，不是长期生产存储；正式 P0 应迁移为 IndexedDB 草稿 + PostgreSQL 权威存储。
2. 语义节点卡当前使用 SVG 画布实现；正式 P0 可评估 G6 React 富节点或统一的 SVG 组件系统。
3. 聚合节点目前是样例数据中的显示节点，尚未实现按关系数量自动创建、分批展开或服务端按需加载。
4. 调查路径当前展示案件图的连通路径；后续需要增加明确的“当前根节点 + 展开状态”投影算法。
5. 节点点击与关系点击当前由 SVG 处理；正式 P0 需要统一 G6 与业务事件/布局策略。
6. 简报已包含节点与关系备注，但尚未自动归纳更细的主体簇、跨平台链路与群聊衍生结构。
7. 新建案件中的初始线索类型目前覆盖 QQ、微信、手机号、IP、群聊，后续补设备、平台账号、组织。
8. 状态色、主体色和来源色的最终优先级尚需通过真实样本验证；当前以类型色为主、状态以独立标签表达。

## 下一步建议

先由用户直接试用 Demo 的三件事：

1. 从一个微信或 QQ 开始，连续补一批手机号、QQ、群聊；
2. 切换调查路径和关系网，判断是否能回想起排查过程；
3. 看自动简报是否像“当前可调查结构”，而不是流水账。

根据反馈，优先改录入路径和聚合语义，再迁移到正式 P0 架构。
