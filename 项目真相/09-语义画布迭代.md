# 语义画布迭代：节点状态、链路备注与显示逻辑

## 触发反馈

用户认可“案件 + 快捷录入 + 图谱”的方向，但指出第一版 Demo 存在以下问题：

- 视觉更像基础图组件，缺少成熟产品的案卷感与层级；
- 节点无法表达账号是业务号、生活号、小号、已失效或待核实；
- 关系链无法记录“怎么推出来的”“要注意什么”；
- “延伸选择”不清楚，不知道结果要填 QQ、微信、手机号、IP 还是群聊；
- 同机扩散、同 IP 扩散、群聊扩散等不同扩展逻辑没有被显著表达；
- 脑图节点过于简陋，无法帮助用户回想案件排查过程。

## 设计调整

### 1. 节点不再是圆点，而是语义卡

节点卡固定三层信息：

```text
类型 · 状态
核心值
角色 / 备注提示
```

示例：

```text
QQ号 · 待核实
QQ 987654321
小号
```

或：

```text
微信号 · 有效
wxid_lyra
业务号 · 有备注
```

这样用户无需打开详情，就能知道它是什么、当前可靠性、在画像中的角色，以及是否存在需要回看的说明。

### 2. 节点标注采用两类，避免混杂

**状态**：有效、待核实、已失效、已排除。  
**角色**：业务号、生活号、小号、核心账号、扩散节点、未标注。

状态回答“这条线现在还值不值得用”，角色回答“它在主体画像里像什么”。二者不混在同一个随意备注中。

### 3. 每条关系链有独立语义

关系不只是“连了一根线”，至少包含：

```text
关系名称：微信关联手机号 / 同机登录 / 加入群聊
扩散方式：账号链扩展 / 跨平台映射 / 同机扩散 / 同 IP 扩散 / 群聊扩散 / 人工关联
关系状态：有效 / 待核实 / 已失效 / 已排除
关系备注：怎么推出来的、要注意什么
```

例如：

```text
QQ 123456789 — 同机登录 → Device-A1
扩散方式：同机扩散
备注：同机记录将 QQ 123456789 与 wxid_nova 连接。
```

### 4. 快捷延伸按钮必须把对象类型说清

第一版的“关联账号”过于模糊。新文案使用“动作 + 对象类型 + 扩散方式”三层表达：

```text
补关联手机号
手机号 · 跨平台映射

补QQ号
QQ号 · 账号链扩展

补登录IP
IP · 同 IP 扩散

补关联群聊
群聊 · 群聊扩散
```

用户不需要猜系统期待填什么，也能知道这条枝会如何影响后续图谱。

### 5. 显示颜色规则

- **节点类型色**：QQ、微信、手机号、IP、设备、群聊、平台账号、主体簇、组织各有固定低饱和色；
- **节点状态**：显示为独立小标签，避免与类型颜色抢语义；
- **关系扩散方式**：显示在线条上的胶囊关系标签以及右侧链路列表；
- **主体颜色**：暂不在第一版按主体给节点整体换色，因为同一节点可能处于多个主体簇，按类型色更稳定；主体归属以卡片标签、局部高亮和关系网筛选表达。

## 当前 Demo 已实现

- 节点编辑：状态、角色、备注；
- 关系编辑：状态、扩散方式、推导/注意事项备注；
- 语义节点卡；
- 明确的快捷延伸按钮；
- 关系链列表；
- 含节点/关系备注的 Markdown 简报导出；
- 语义化调查路径和主体关系网截图。

## 后续待做

1. 自动把同一主体簇的局部路径做更强的视觉高亮；
2. 对已失效/已排除关系提供默认弱化或过滤；
3. 对备注较长的节点/关系提供悬浮预览与全文详情；
4. 为聚合节点实现真实的按需展开与批次加载；
5. 基于用户操作记录调整不同节点类型的快捷延伸顺序。
