# 上线程序优化方案

> 状态：方案评审稿；本轮不直接把 Demo 改造成安装程序。  
> 目标：把“手工快录入 + 自动关系图 + 可回忆案件过程”的 Demo 收敛为可长期使用的本地优先案件工作台。

## 1. 结论：正式产品做桌面应用，不做纯网页

### 推荐形态

**一个本地优先桌面应用，开发时仍用网页技术，正式交付为 Windows `.exe` / `.msi` 和 macOS `.dmg` / `.app`。**

推荐技术路线：

```text
React + TypeScript（界面与图谱）
Tauri v2 + Rust（桌面壳、文件、导出、数据库命令）
SQLite（单机案件权威数据）
本地资源目录（导出包、附件、快照）
```

不是“网页和 EXE 二选一”：

- **开发 / 设计验证**：继续用浏览器跑前端，速度快；
- **正式使用**：打成桌面安装程序，数据只在本机目录，具备系统文件选择、离线存储、备份恢复、打印和安全更新能力；
- **后续如果确实需要**：再做只读网页端或团队服务端，不反过来让网络决定单机案件能不能打开。

### 为什么不建议把纯网页作为正式形态

| 维度 | 纯网页 | 本地桌面应用 |
|---|---|---|
| 离线打开案件 | 浏览器缓存可做，但不可靠 | 原生支持，案件库就是本机数据库 |
| 长期数据与备份 | 容易散落在浏览器缓存或服务器 | 数据目录、导出包、快照路径可见且可控 |
| 大图性能 / 本地文件导出 | 受浏览器与下载行为约束 | 可控的本地文件、SQLite、PDF/图片生成 |
| 安装与升级 | 无安装，但版本漂移难控 | 可签名安装、版本号、更新说明、回滚策略 |
| 跨平台 | 浏览器天然跨平台 | 一套代码打 Windows / macOS 安装包 |
| 适合本项目 | 仅适合 Demo | **适合正式单机案件工作台** |

### 为什么选 Tauri v2，不选 Electron 作为首选

- 现有界面可继续使用 TypeScript 前端；不必推倒视觉和图谱层；
- Tauri 官方支持 Windows、macOS 等平台分发，Windows 可生成安装器，macOS 可打包为 DMG；
- 官方 SQL 插件支持 SQLite，并支持迁移；
- 权限默认收紧，文件、数据库、导出等高权限能力要显式授予；
- 可用签名更新机制；更新包必须签名，客户端校验不可关闭。

Electron 不是不能做：若后续强依赖某些 Chromium/Node 原生扩展，才重新评估。当前需求以本地 SQLite、文件导出、图谱交互为主，Tauri 的体积、权限边界和本地能力更合适。

## 2. 产品定义与上线原则

### 核心承诺

用户只负责把已查到的信息放进合适的位置；系统负责：

1. 减少输入和重复；
2. 让关系以可读路径和局部网络呈现；
3. 自动保留案件排查脉络；
4. 在任意时刻输出“能看、能复核、能继续查”的文字概括和脑图；
5. 不因误操作、升级、崩溃或换电脑丢案件。

### 上线前必须坚持的边界

- 一个案件是一个独立工作区，不自动跨案混图；
- 图谱底层是多对多关系；脑图只是一个可导出的阅读视图；
- 快捷关联默认全量可用，但日常推荐项可根据对象类型置顶；
- 自动生成的文字只总结已录入的节点、关系、状态和备注，不补造事实；
- 数据导出、备份、归档、删除都必须可追溯、可恢复或有明确不可逆确认。

## 4. 案件库：从左侧列表升级为案件管理中心

### 4.1 默认列表结构

左侧案件库由单一列表改为四个稳定区段：

```text
置顶
进行中
已归档
回收站
```

每张案件卡只保留高频信息：

```text
案件名
状态 · 最近编辑时间
节点数 · 关系数
```

不在左侧塞背景全文、导出状态或复杂标签。

### 4.2 排序与拖动

- 默认排序：置顶 → 手动排序 → 最近编辑；
- 用户可以在同一状态区段内拖动排序；
- 拖入“置顶”区即置顶；拖回普通区取消置顶；
- 手动排序写入 `case_order`，不会被最近编辑自动打乱；
- 提供“按最近编辑 / 按创建时间 / 按名称 / 手动排序”切换；
- 归档案件不参与进行中排序。

### 4.3 右键菜单

参考成熟本地知识库的上下文菜单方式，案件卡右键菜单固定为：

```text
打开
重命名
复制为新案件
置顶 / 取消置顶
移动到分组（P1）
────────
归档…
导出案件包…
────────
移到回收站…
```

右键菜单不是隐藏主要能力：归档和删除同样在案件详情的“更多”菜单可见；右键只是高效入口。

### 4.4 归档：必须保留原案名，同时允许归档名

用户要求“归档要可以自定义名字”，正式模型设为：

- `title`：案件正式名称，永远保留；
- `archive_title`：归档显示名，可选，例如“2026Q3 已交接 · 北岸账号关联”；
- `archived_at`、`archive_note`、`archived_by`：归档时间、说明、操作者（单机先记录本地用户）；
- 归档后只读默认，但可以“恢复并继续编辑”；
- 归档前自动创建一份快照；
- 归档不会删除图、附件、导出历史或操作历史。

### 4.5 删除：回收站而非直接删除

- “移到回收站”立即从正常列表消失，但保留全部数据；
- 回收站支持恢复、查看删除时间、批量清空；
- 默认保留 30 天；正式 P0 可设为“永不自动清空”，由用户手动永久删除；
- 永久删除必须展示：案件名、节点数、关系数、附件数、预计释放空间；要求输入案件名确认；
- 永久删除前必须提供“先导出案件包”按钮；
- 每一次删除/恢复写入操作历史。

## 5. 快速录入与图谱优化

### 5.1 快捷关联不等于同时展示所有按钮

现有“全量入口”是正确的数据能力，但正式产品不能让右栏永久堆 12 个按钮。

正式交互分两层：

1. **对象相关置顶区**：最多 4 个，例如选中 IP 时优先显示“机房信息、活跃位置、同 IP 账号、同机设备”；选中微信时优先显示“手机号、QQ、活跃位置、平台账号”。
2. **全部关联**：展开后显示完整字典与自定义关联。

这样满足“任何对象都能填任何关联”，也不牺牲日常懒人操作。

### 5.2 位置与机房

- `活跃位置`：账号的活动地区 / 城市 / 站点，支持地点文本、时间范围、备注；
- `机房信息`：IP 环境属性，如 IDC、云区域、自治域、出口类型、机房文本；
- 两者不能合并，也不能根据一方自动推导另一方；
- 正式数据模型中将它们做成独立对象和独立关系类型。

### 5.3 图谱大数据策略

- 路径阅读默认只显示主树；回连显示为弱化虚线，可按“显示回连”临时开启；
- 分支超过阈值时以聚合节点显示：`关联 QQ（18）`、`群成员（56）`；
- 聚合节点展开采用分页，例如每次 50 个，而不是一次性铺开数百节点；
- 节点拖动只保存用户覆盖坐标，自动布局始终可重新应用；
- “阅读”是默认视图；“总览”仅用于看分支边界；
- 关系网默认一跳，两跳显式展开；全案网络不作为默认视图。

### 5.4 键盘和效率

P1 要补齐：

- `⌘/Ctrl + K`：全局搜索案件、对象、关系；
- `N`：新建案件；
- `A`：当前节点添加关联；
- `E`：编辑当前节点；
- `Space`：画布拖动模式；
- `⌘/Ctrl + Z`、`Shift + ⌘/Ctrl + Z`：撤销 / 重做；
- 可配置的批量粘贴解析：换行、逗号、制表符、带前缀文本。

## 6. 导出：从“导出一个 Markdown”改为四种清晰产物

用户要的是“**一段话概括 + 脑图**”，不是一堆字段表。

### 6.1 一键简报（默认入口）

按钮名称：`导出案件简报`。

生成一个文件夹或 ZIP，至少包含：

```text
案件简报.md
关系脑图.svg
关系脑图.png
案件全量关系.csv
```

`案件简报.md` 的首段为可直接转发/复制的概括，模板：

> 本案以【初始线索】为起点，当前已形成【N】个对象、【M】条关系。主链为【A → B → C】；其中【关键对象】连接【X】类账号/环境/社交线索。已标记【重点/待核实/失效】事项【N】项；下一步建议优先补充【尚未展开的高价值分支】。

后续段落按：主链、账号画像、环境与社交、重点/待核实、备注和下一步生成。只有结构化事实和用户备注进入简报。

### 6.2 脑图导出

脑图是“阅读投影”，不是数据源。

P0 导出：

- **SVG**：可无损放大，适合文档和打印；
- **PNG**：适合即时发送；
- **HTML**：可离线打开、折叠分支查看；
- **PDF**：由 SVG/HTML 排版生成，可选择横向 A3 / A4。

P1：评估并接入 Mind Elixir 的 JSON / 图像 / XMind 生态导出能力；`.xmind` 兼容性需用 XMind 实测后才对外承诺。

### 6.3 数据导出

- 全量关系：CSV 和 XLSX；
- 节点表、关系表、备注表、操作历史分 Sheet；
- 所有导出带生成时间、产品版本、案件 ID、快照版本；
- 默认不把回收站内容放入导出。

### 6.4 案件包：迁移和交接的唯一标准

扩展名建议：`.casepack`，实质为带 manifest 的 ZIP：

```text
manifest.json          # 版本、校验、案件元数据
case.sqlite.json       # P0 可用 JSON；P1 切 SQLite 子库或规范 JSON
attachments/
exports/
README.md
checksums.sha256
```

要求：

- 导入时先校验 schema 版本、附件校验值和对象数量；
- 以“新案件导入”为默认，避免覆盖现有案件；
- 覆盖恢复必须先自动备份现有案件；
- 案件包可作为交接、迁移、灾备和正式归档材料。

## 7. 本地数据、备份与恢复

### 7.1 数据目录

桌面程序的数据不放安装目录；统一落在应用数据目录：

```text
AppData / Application Support
├─ casework.db
├─ attachments/
├─ snapshots/
├─ exports/
├─ backups/
└─ logs/
```

更新程序不会触碰该数据目录。

### 7.2 SQLite 结构

核心表：

```text
cases
case_order
entities
relations
entity_notes
relation_notes
attachments
case_snapshots
case_exports
case_operations
app_settings
schema_migrations
```

关键设计：

- 所有关系使用稳定 UUID，不用 `source-target` 拼接 ID；同一对象之间可存在不同时间、不同依据的多条关系；
- `relations` 记录类型、方向、状态、扩散方式、备注、时间范围、置信度和来源引用；
- `case_operations` 追加记录创建、编辑、归档、恢复、删除、导出、导入和版本变更；
- 快照是案件级不可变副本，提供“恢复为此版本”和“另存为新案件”。

### 7.3 自动保存与快照

- 每次编辑 500ms 防抖后落库；
- 重要动作（归档、导出、导入、删除前、数据库迁移前）立即创建快照；
- 每个案件保留最近 50 个自动快照，手动快照永久保留，数量可配置；
- 启动时检测上次异常退出，提供“恢复上次工作区”而非静默覆盖。

### 7.4 备份

- 每日首次打开后做增量备份；
- 手动“立即备份”生成带日期的案件包；
- 备份健康状态显示最后成功时间、大小、校验结果；
- 恢复必须是导入式，不直接覆盖在线数据库；
- 云同步、网盘同步不进入 P0；未来做同步时需采用单写者/冲突处理方案，不能直接把 SQLite 文件丢进同步盘。

### 7.5 本地安全

- 本地数据库是权威存储；
- 若用户需要加密保护：采用经验证的数据库加密方案，密钥放系统安全存储或 Stronghold；不能把“密码”只保存在前端 localStorage；
- Tauri 权限按最小化配置：数据库、导出目录、文件对话框、更新各自单独授权；
- 不提供任意 shell 执行权限；
- 生产更新必须签名，发布私钥只保存在受控发布环境。

## 8. 应用壳与上线体验

### 8.1 首次启动

首次启动只做三步：

1. 设置本地数据位置与备份位置；
2. 创建第一个案件，或导入 `.casepack`；
3. 展示一个可关闭的“如何从起点补关联”的短引导。

不要求登录、不要求联网、不要求配置外部数据源。

### 8.2 设置

设置页分为：

```text
通用：外观、语言、快捷键
案件：自动快照、聚合阈值、回收站保留策略
导出：默认目录、PDF 页面、脑图样式
数据：备份、恢复、数据目录、数据库检查
更新：版本、检查更新、更新渠道
安全：本地访问保护、密钥状态（若启用）
```

### 8.3 发布与更新

- Windows：优先提供 NSIS `.exe` 安装包，也可按企业部署需要补 `.msi`；
- macOS：`.dmg` + 签名与公证；
- 每个版本包含版本号、变更说明、数据库迁移兼容说明；
- 内置检查更新，但默认由用户确认下载和安装；
- Windows 安装更新前强制落库与快照，因为安装时可能退出应用；
- 更新源使用 HTTPS + 签名验证；私钥不得写入仓库或 `.env`。

## 10. 上线验收门

### 功能

- 新建案件到输入第一条关系不超过 30 秒；
- 从当前节点新增任意预设或自定义对象不超过 2 次点击 + 输入；
- 归档、恢复、移到回收站和永久删除都可准确验证；
- 每个导出包能在干净机器导入为新案件；
- 文字简报只覆盖已录入的节点、关系、备注和状态；
- 脑图、数据表和简报指向同一个案件快照版本。

### 稳定性

- 强杀应用后重新打开，不丢失已确认保存的最近编辑；
- 数据库迁移失败必须完整回滚；
- 1000 节点 / 2000 关系案件下，默认路径阅读和一跳关系保持可操作；
- 聚合展开不阻塞主线程超过可感知阈值；
- 备份可校验，恢复演练通过。

### UX

- 删除是可逆的，永久删除有明确对象、范围和确认；
- 导出默认给“概括 + 脑图”，不是把用户扔进格式选择器；
- 阅读模式不为塞进全图而牺牲文字可读性；
- 所有常用动作有快捷入口、明确成功反馈和撤销路径。
