# 本地自动化接口与验证

> 状态：已实现并完成 CLI / MCP / SQLite 闭环验证。当前发布版本：0.6.0。

## 目的

让桌面工作台不再只能依赖手工点击。对话指令、CLI 脚本和桌面 UI 操作同一份本地案件库；它们不通过网络服务，也不需要账号体系。

```text
自然语言 → 本地 MCP（stdio）→ CLI → 受控案件命令 → SQLite
                                           ↓
                                  桌面应用检测变更并刷新
```

## 结构

- `src-tauri/src/case_core.rs`：共享案件核心。负责数据库目录、结构迁移、案件读取、创建、关联录入、对象/关系标记、归档、回收站、导出和变更版本。
- `src-tauri/src/bin/clue-workbench-cli.rs`：本地 CLI。所有输出为 JSON，供脚本与 MCP 适配器调用。
- `integrations/mcp/clue_workbench_mcp.py`：无第三方依赖的 stdio MCP 适配器。
- `release/macOS/automation-0.6.0/`：随 0.6.0 发布的 CLI、MCP 服务与 MCP 配置模板。

## 工具边界

MCP 只提供受控高层命令：案件读取/创建、批量关联（可带命名列）、案件概览/路径分栏、对象/关系标记、撤销/重做、归档、恢复、移入回收站、导出、启动应用。

明确不提供：

- 任意 SQL；
- 任意文件路径读取或写入；
- 自动永久删除；
- 网络上传或外部数据访问。

永久删除继续只允许在桌面端回收站中手动输入案件名确认。

## 桌面同步

每一个 CLI/MCP 写入会更新 `workbench_meta.revision` 和案件 `updated_at`。桌面端每两秒读取变更版本；发现外部写入后，刷新当前案件及案件列表。因此可以在对话中补关系，桌面端会同步显示，而不是把 UI 和自动化分成两份数据。

## 验证证据

`app/scripts_validate_cli_mcp.py` 已验证：

1. 创建一份独立的脱敏闭环案件；
2. CLI 批量录入 3 个值（其中 1 个重复），确认只新增 2 个手机号；
3. CLI 修改对象状态、角色、备注、重点色与重点标记；
4. CLI 导出概括、SVG 脑图和 CSV，确认三份文件存在；
5. MCP 初始化、工具清单和 `clue_add_relationships` 调用；
6. MCP 新增 2 个 QQ 关联后，复核案件为 6 个实体、5 条关系；
7. CLI 执行撤销后回到 4 个实体、3 条关系；重做后回到 6 个实体、5 条关系；
8. 将测试案件移入回收站，确认没有发生永久删除。

此外，发布目录的 CLI 与 MCP 文件已通过 SHA-256 与测试版本逐字节一致性校验；0.6.0 `.app` 已通过签名检查，DMG 已通过镜像校验；CLI 已实际拉起 0.6.0 应用。

## 已知限制

- MCP 配置文件已生成，但需要由支持 stdio MCP 的宿主导入或重载后才会在该宿主的工具列表中出现。
- 原生 WebView 的“收到 revision 后画布刷新”已完成编译与启动验证；仍需要在下一次真实脱敏案件操作中做一次肉眼验收，确认你看到的画布切换体验符合预期。
- 当前 CLI 是 macOS 路径版本；Windows 发行时将使用同一 Rust 核心产出 `.exe` 并提供对应 MCP 配置。
