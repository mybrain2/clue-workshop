# 开放问题与验收门

> 更新至 0.7.7。只记录尚未解决或尚未以真实案例验收的事项。

## P0：下一个可用性与可追溯性门

1. **导入批次审计与回滚**
   - 当前：文本/Excel/CSV/OCR 确认后写入关系图，无法准确回答“本次导入产生了哪些对象和关系”。
   - 验收：每次导入有 batchId、来源摘要、数量、映射规则；可以仅回滚该批次。

2. **附件模型与证据关联**
   - 当前：存在 attachments 目录，但无附件表、哈希、案件/节点关联、可见列表和删除规则。
   - 验收：附件导入记录 SHA-256、MIME、原名、时间、关联对象；不会静默删除用户原文件。

3. **脱敏真实案件人工验收**
   - 当前：90 实体/89 关系脚本验证结构，但未验证调查人员阅读主链和录入手感。
   - 验收：用户完成建案、批量导入、定位关联、标记重点/失效、案件包导出与导入五项任务并反馈。

4. **画布手感验收**
   - 当前：非被动滚轮和锚点计算已构建/启动验证，但需用户在长图中连续滚轮和横向滚动后确认。
   - 验收：节点不向鼠标上方漂移；节点拖动无浏览器文本选择；选中高亮稳定。

## P1：进入内部试用后处理

1. 图内搜索和按对象类型、关系状态、重点的筛选；筛选不能改变原始数据。
2. CSV/XLSX 输出字段合同、编码、列顺序和外部工具读回验证。
3. 案件包版本兼容策略，包含旧包、缺字段、未知字段的诊断。
4. 右侧快捷卡分组，在不增加点击的前提下降低 11 类入口的扫描负担。
5. `App.tsx`、`app.css`、`case_core.rs` 的结构拆分和 UI 冒烟回归。
6. 运行日志脱敏和可控清理策略。

## P2：需要新产品决定

- 跨案件关联：必须保持案件隔离且可显式解释，不能偷偷合并同值对象。
- 多人协作和权限：需要同步、冲突和审计模型，不是 UI 开关。
- 时间线与地图：先确认数据来源、隐私边界与业务任务。
- 加密存储：需要密钥生命周期、备份恢复和用户可理解的故障处理。
- XMind 原生文件编辑或导入：必须保持图数据与导入结果的可追溯关系。

## 已解决后如何更新

完成一项时：

1. 在 `03-决策记录.md` 记录取舍、替代方案与影响模块。
2. 更新 `00-AI接手总览.md`、产品事实、模块地图、数据或体验文档。
3. 删除或标记本文件条目，并写入 `CHANGELOG.md`。
4. 为该项加入可重复验证脚本或真实交互验收记录。
