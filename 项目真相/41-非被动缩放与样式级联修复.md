# 41 - 非被动缩放与样式级联修复（0.7.7）

## 复盘

用户反馈 0.7.6 的缩放和右侧卡片均未改变。实际检查发现两处没有被真正验证：

1. React `onWheel` 在桌面 WebKit 环境可能不能可靠阻止容器原生滚动；虽然视口状态计算正确，滚动和缩放会同时发生，视觉上仍表现为内容向鼠标上方漂移。
2. 右侧卡片存在后定义的通用 `.quick-entry-grid button` 规则，覆盖了先前用于缩小卡片的同等优先级规则。实际计算样式仍是 78px 高、13px 标题，而不是声明的 49px / 10px。

这两项都属于“代码写了但最终渲染未命中”，不应在未核对实际样式和桌面启动结果前宣称完成。

## 修复

- 去掉 JSX `onWheel`，在画布 DOM 上直接注册 `{ passive: false }` 的原生滚轮监听器，明确 `preventDefault()`；滚轮只改变 `viewport`，不会同时推动容器滚动。
- 继续使用单一 `viewport` 状态，在同一函数式更新中计算 `zoom` 和 `pan`；锚点仍包含画布 `scrollLeft`/`scrollTop`。
- 将原生 wheel effect 移至条件渲染之前，修复首次无案件、后续加载案件时的 React Hook 顺序错误；该错误曾导致发布版白屏，已在最终发布包启动截图中验证恢复。
- 右侧卡片规则改为 `.desktop-app .inspector ...`，提高选择器优先级，使最终计算样式确实为：面板 `14px 12px 12px`、标题 `14px`、按钮 `10px`、按钮最小高度 `49px`、说明 `8.5px`。

## 实测

- 自动化浏览器读取最终计算样式，已与目标值一致。
- 画布缩放计算用三组不同缩放/平移/锚点数据断言，锚点误差为 0。
- TypeScript/Vite、Rust、90 实体/89 关系多跳回归、CLI/MCP 回归全部通过。
- 最终 `0.7.7` 发布 App 已启动并加载案件图；截图 `qa-0.7.7-final.png` 可见界面。
- App 签名、DMG 校验通过，发布 CLI SHA-256 与构建 CLI 一致。
