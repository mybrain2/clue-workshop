# 设计 Skill 候选与 iOS 重设计方向

## 结论

首轮 Demo 的失败不在于“缺少更多颜色或标签”，而在于：

- 把每个节点的全部语义同时放到了画布上；
- 把右侧检查器、图、关系标签都做成同等视觉重量；
- 用卡片和边框替代了空间层级；
- 关系标签漂浮在图上，干扰主路径阅读；
- 没有明确区分“阅读状态”和“编辑状态”。

下一版不再继续给卡片加内容，而是采用 **iOS/macOS 专业工具式的清晰、克制、层级分明** 方向：内容优先，工具退后，详情按需出现。

## GitHub 候选

### A. Taste Skill：适合做“现有项目重设计”的审美约束

- 仓库：<https://github.com/Leonxlnx/taste-skill>
- 许可证：MIT。
- 活跃信号：2026 年持续更新；README 显示 v2 为实验性版本。
- 最匹配子 Skill：`redesign-existing-projects`、`minimalist-ui`。
- 可用价值：对现有界面做布局、排版、密度、层级的系统重构；提供设计方差、动效强度、视觉密度三个可调参数。
- 风险：默认 `design-taste-frontend` 已是 v2 experimental；不应直接安装为唯一设计规则。对本项目要固定为低动效、中高信息密度、低到中等布局方差。

推荐配置：

```text
DESIGN_VARIANCE: 3/10
MOTION_INTENSITY: 2/10
VISUAL_DENSITY: 7/10
```

含义：不做营销页式大构图和强动效；保留专业工具的紧凑、清晰与成熟留白。

### B. Emil Kowalski Skills / apple-design：适合做“iOS 操作感”约束

- 仓库：<https://github.com/emilkowalski/skills>
- 用途：面向设计师与工程师的 UI、动画和 Apple 式 Web 交互技能。
- 仓库可确认的子 Skill：`apple-design`、`emil-design-eng`、`prototype`、`pick-ui-library` 等。
- 安装方式：`npx skills@latest add emilkowalski/skills`。
- 可用价值：Apple 式层级、材质、即时反馈、连续可打断交互、浮层锚定与高密度桌面工具的空间结构。
- 安全审阅：已读取的 `apple-design` 文档不包含安装脚本、网络调用或数据上传；仍须在实际安装前对完整下载内容进行安全审计。

### C. Platform Design Skills：只作为 HIG 查阅参考

- 仓库：<https://github.com/JayNgDigitalCaptain/platform-design-skills>
- 许可证：MIT。
- 用途：官方平台设计规范的 Agent Skill 集合，含 iOS、iPadOS、macOS、Web。
- 可用价值：查阅 iPad/macOS 的侧边栏、工具栏、键盘快捷键、检查器和多栏布局规则。
- 不作为主设计 Skill：它更像规范集合，不提供对现有复杂 Web 工作台的重设计方法。

## 安装建议

当前不立即安装。若用户确认进入下一轮重设计，建议顺序：

1. 对 `emilkowalski/skills` 进行完整安全审计；
2. 通过审计后，仅安装/加载 `apple-design`；
3. 对 `Leonxlnx/taste-skill` 进行完整安全审计；
4. 通过审计后，仅安装 `redesign-existing-projects` 与 `minimalist-ui`，不采用实验性默认 v2 作为唯一规则。

## 新视觉方向：macOS 案卷工具，而非 iOS 卡片界面

用户说“类似 iOS 的干练”，本项目应取其 **Clarity / Deference / Depth**，但不能生搬 iPhone 卡片语言。桌面案件工作台更接近 macOS 的侧栏、检查器、工具栏和内容画布。

### 原则

1. **Clarity（清晰）**
   - 一眼先看出案件、当前路径、当前对象。
   - 节点只显示核心值和一个状态点，不显示所有语义。
   - 关系标签只在选中节点的局部路径显示，其余关系不在画布上飘字。

2. **Deference（退让）**
   - 侧栏、工具栏、检查器是工具层；画布才是内容层。
   - 类型、状态、角色、备注不抢主内容，只在选中时进入 Inspector。
   - 移除无意义的边框、胶囊、说明小字和持续可见的标签墙。

3. **Depth（深度）**
   - 仅通过三个稳定层级区分：导航层、画布层、Inspector/Popover 层。
   - Hover、选中、编辑通过非常轻的材质、阴影、焦点环表达，不使用大面积卡片叠加。

## 新画布结构

```text
左：案件库（固定、轻）
中：纯画布
  顶部：案件名 / 当前视图 / 少量工具
  画布：节点与主路径
右：Inspector（选中时才有详细语义）
```

### 画布节点

默认节点只显示：

```text
[类型色点]  wxid_lyra
             ● 有效
```

选中后节点才展开为紧凑信息单元：

```text
微信号  wxid_lyra                           [编辑]
有效 · 业务号
备注：公开平台留有同一联系方式
```

聚合分支采用单行：

```text
+ 关联 QQ 18 个
```

而不是一个完整“折叠分支卡片”。

### 关系线

- 默认：无关系文字，仅用细线与小型方向点表达连接。
- 选中节点时：只显示其一跳关系的关系名，例如“同机登录”“跨平台映射”。
- 选中一条线或在 Inspector 内：再展开状态、扩散方式、推导备注。

### 快速录入

取消右侧固定的多按钮矩阵。改为点击节点后，在节点旁出现一个上下文 Popover：

```text
添加关联
[手机号] [QQ号] [微信号] [IP] [群聊]
```

选择类型后才出现第二步：

```text
手机号
输入或粘贴结果
关系：跨平台映射（默认，可改）
```

这样是二步选择，第一次只面对对象类型，不用同时理解“动作、对象、扩散方式”三层文案。

### 状态与备注

- 节点状态使用一个小圆点：绿=有效、黄=待核、灰=失效、红=排除；文字只在 Inspector 与筛选中出现。
- 账号角色不在节点常显，只在 Inspector 内作为可切换 segmented control。
- 备注不在节点常显；有备注的节点右上角显示轻量注记符号，点击 Inspector 查看。
- 关系链备注不漂浮在画布上；选中边后在 Inspector 编辑。

## 下一版原型必须验证

1. 用户是否能在不读说明的情况下完成：点节点 → 选“手机号” → 粘贴结果 → 保存。
2. 画布在未选择任何对象时，是否能快速看懂主路径而非被标签淹没。
3. 选择节点后，是否能在右侧看清状态、角色、备注和链路来源。
4. 选择一条关系后，是否能知道“这条关系怎么来的”和“如何扩散”。
5. 已失效、已排除节点是否能在默认画布中低权重展示，而不是抢视线。
