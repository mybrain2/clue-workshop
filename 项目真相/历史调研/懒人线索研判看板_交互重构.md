# 懒人线索研判看板：交互重构

## 产品定位

这不是数据查询系统，也不是要求用户整理资料的“专业工具”。它就是一个**把你已经查到的信息，快速塞进结构里，然后自动长成关系图和简要线索报告的录入器**。

用户完成一件事即可：**选一个关系，输入一个值，按回车。**

其余事情由系统完成：建节点、连线、去重、布局、归类、生成时间线、补全摘要。

## 不要做什么

- 不做复杂的多页表单；
- 不要求先建“人”、再建“账号”、再选关系；
- 不要求每条线都填来源、时间、备注；
- 不把图谱操作做成专业软件；
- 不把“下一步建议”变成工作流或待办管理系统；
- 不把外部/内部数据接入作为第一版范围。

这些字段可以存在，但只能藏在“更多信息”里，绝不阻塞快速录入。

## 核心体验：一条线 3 秒录完

### 起点

新建案件只填两项：

1. 案件名称；
2. 一段任意长度的背景描述。

背景可以是散文式的。例如：

> 某人涉嫌通过多个社交账号组织活动，已知手机号为 138xxxx，发现其 QQ 与微信可能有关联。

保存后，进入同一个页面：左侧是“快速录入”，中间自动出图，右侧是“线索摘要”。

### 快速录入器

录入器不是“创建实体表单”，而是一句话式的关系填写：

```text
[QQ账号] 关联到 [手机号]  →  输入：123456789 / 13800138000
```

用户只做三步：

1. 点第一个类型，例如 `QQ账号`；
2. 点关系，例如 `关联到`、`同机登录`、`加入群聊`；
3. 点第二个类型并输入值，回车。

系统自动完成：

- 创建或复用节点；
- 将两端节点连起来；
- 给节点打正确的图标和颜色；
- 关系图即时重排；
- 摘要增加一条可读句子；
- 记住这次用过的类型，放到下一次的“最近使用”里。

## 最小交互设计

### 1. 种子卡片

案件进入后，先出现一个大输入框：

```text
我先查到了什么？
[ 例如：QQ 123456789 ]  [添加]
```

输入框左边默认是实体类型选择器，默认显示 `QQ账号`，但可以一键切为：

- 人员/昵称
- QQ账号
- 微信号
- 手机号
- 平台账号
- IP
- 设备
- 群聊
- 地点
- 团伙/组织

输入一次后，系统生成一张实体卡。卡片下方立即出现最相关的下一步按钮：

```text
[关联手机号] [关联微信] [关联平台账号] [同机登录] [加入群聊] [添加备注]
```

不需要用户研究“关系字典”。系统根据当前节点类型只展示常用关系。

### 2. 单击补关系

例如用户点了 `关联手机号`：

```text
QQ 123456789  — 关联手机号 →  [输入手机号]
```

回车后，它立刻收起，图里多一个手机号节点。随后系统在手机号卡片下面显示：

```text
[关联其他QQ] [关联微信] [关联平台账号] [查看共同关系]
```

这种方式使录入天然沿着人的思考路径往下走：查到什么，就把什么补进来。

### 3. 两种录入入口同时保留

**入口 A：卡片式，适合慢慢查。**  
点已有节点，再点关系，再输新值。

**入口 B：快捷句式，适合连续搬运结果。**

```text
QQ 123456789 - 关联手机号 - 13800138000
手机号 13800138000 - 关联微信 - wxid_abc
wxid_abc - 加入群聊 - 海城交流2群
QQ 123456789 - 同机登录 - device:A1B2
```

用户不需要记语法：输入框上方固定显示示例，输入时自动补全实体类型、关系名称和已存在节点。粘贴多行时，一次生成多条关系。

## 关系选择器：按人话分类

不要展示一张几十项的关系下拉框。只展示 5 组：

| 分组 | 用户看到的关系 |
|---|---|
| 账号与联系方式 | 关联手机号、关联微信、关联 QQ、关联平台账号 |
| 登录与网络 | 同机登录、同 IP 登录、在某地登录、共用设备 |
| 社交关系 | 好友、加入群聊、共同群聊、互相关注、共同联系人 |
| 归属与组织 | 属于某人、关联团伙、任职/参与、共同活动 |
| 补充 | 添加地点、添加时间、添加备注、自定义关系 |

对于一个 `QQ账号`，首屏只显示前 4 个最常见按钮；“更多关系”再展开全部。

## 图谱：自动生成，不让用户画

图谱只解决两个问题：谁和谁有关、关系通过什么路径串起来。

- 节点颜色按类型固定，例如账号、手机号、IP、设备、群聊各一种颜色；
- 节点标签永远显示关键值，不显示数据库字段；
- 连线直接写人话，例如“关联手机号”“同机登录”“加入群聊”；
- 选中节点时，只高亮其一跳和两跳关系，其余淡化；
- 按一下 `聚焦此人/账号`，只看与该节点有关的局部图；
- 默认自动布局，用户可以拖动，但不必手动排图；
- 一键切换 `全部关系 / 账号链路 / 设备网络 / 社交关系 / 群聊网络`。

核心原则：**图不是让人编辑的，是让人看懂的。**

## 自动简要线索报告

报告不等待用户写完。每录入一条关系，右侧“线索摘要”实时更新；需要导出时再点 `生成简报`。

输出固定为短、可读、可直接转发的形式：

```markdown
# 线索情况简报

## 背景
{用户填写的案件背景}

## 当前已录入线索
- 已录入 1 个手机号、2 个 QQ账号、1 个微信号、1 台设备和 2 个群聊。
- QQ账号 123456789 与手机号 13800138000 存在关联；该手机号还关联微信号 wxid_abc。
- QQ账号 123456789 与微信号 wxid_abc 均出现于设备 A1B2。
- 微信号 wxid_abc 加入“海城交流2群”，该群另有 {n} 个已录入账号。

## 关键关系
1. 手机号 13800138000 是当前账号链路的连接节点，已连接 QQ账号和微信号。
2. 设备 A1B2 连接 QQ账号 123456789 与微信号 wxid_abc，形成同机登录关系。
3. “海城交流2群”是当前社交关系中的共同群聊节点。

## 当前结构
- 核心节点：手机号 13800138000、设备 A1B2、海城交流2群。
- 关系规模：6 个节点，5 条关系。
```

生成规则只基于用户已填内容：

- 按实体数量、关系数量和连接度自动归纳；
- 自动找出连接最多的 1—3 个节点作为“核心节点”；
- 自动找最短关联链，例如“QQ → 手机号 → 微信”；
- 不补写用户没有输入的事实；
- 需要更自然的措辞时，只改写表达，不新增信息。

## 懒人提醒：不是“建议你查什么”，而是“你还差哪一格”

这部分改成轻提示，不做任务系统。

例如：

- 用户刚输手机号：`可继续补：关联 QQ / 微信 / 平台账号`；
- 用户刚输 IP：`可继续补：登录账号 / 设备 / 登录地点`；
- 用户刚输群聊：`可继续补：群内账号 / 群主或管理员 / 共同群聊`；
- 某节点没有任何关系：`这条线索目前还是孤立的，要不要补一个关联？`；
- 图中已经存在同一值：`已存在“wxid_abc”，直接连过去还是新建？`。

所有提示都可以关闭，不能要求用户完成。

## 第一版只需要的页面

1. **案件列表**：继续上次案件；
2. **案件看板**：快速录入 + 自动图谱 + 实时摘要；
3. **简报预览**：一键生成 Markdown/PDF；
4. **设置**：修改实体名称、关系名称、节点颜色。

第一版甚至不必拆“实体管理”“关系管理”“时间线”“任务管理”这类专业模块。它们只会增加懒人的操作成本。

## 第一版技术实现

- 前端：React + TypeScript；
- 关系图：Cytoscape.js 或从 Flowsint 中借鉴图谱交互；
- 业务数据：本地优先 SQLite / IndexedDB 即可，后续再换服务端；
- 自动摘要：纯规则模板先做，保证马上能用；后续再加本地模型做润色；
- 导出：Markdown 优先，PDF 第二步再加。

不需要 Neo4j 才能做 P0。第一版用实体表和关系表即可，图谱库负责可视化；等真实使用量和多跳查询复杂度上来，再切 Neo4j。这样能把第一版从“搭一套平台”降到“做一个真能省事的录入器”。

## P0 验收标准

给用户一份自己查到的内容，目标是：

- 10 秒内建立第一个线索节点；
- 3 秒内新增一条常见关系；
- 连续粘贴 20 行关系，不需要逐条建表；
- 不做排版即可得到可看的结构图；
- 一键得到一页以内的线索情况简报；
- 所有细节字段都是可选项，不影响快速录入。

## 现有开源调研如何纠偏

保留原调研，但参考顺序调整为：

1. **Casebook**：优先看它如何把“新增材料/新建连接/生成导出”做成低阻力操作；
2. **Flowsint**：优先借其图谱探索和实体详情交互，不把它的 enrichment 当重点；
3. **sift-kg**：只保留“自动生成摘要”的参考，不将其文档抽取放进 P0；
4. **POLE**：只取实体关系分类思想，不让模型反过来决定用户怎么填；
5. **其余项目**：不进入 P0。

一句话：**先做“人脑外挂记事板”，再考虑把它长成复杂研判平台。**
