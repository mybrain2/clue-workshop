# 线索研判懒人工作台：按截图纠偏后的产品方案

## 一句话定义

把你查到的账号、手机号、IP、设备、好友、群聊、公开平台账号等结果，按“**一个线索往外展开一枝**”的方式塞进去；系统自动维护全量关系、生成 XMind 式线索脑图、全量表和可继续调查的简报。

不是 Excel，不是填资料卡，不是让你先理解一套图谱模型。

## 先说截图的问题

截图本质上是在把“关系链”压成一行一行的人员资料：

```text
账号组合 | 关联昵称 | 关联关系 | 关联账号 | 昵称 | 最近登录时间 | 实名 | 关联手机 | 最后登陆地 | 关联群 | 备注
```

这会自然产生五个问题：

1. **一条账号链被拆碎**：同一个 QQ、微信、手机号会在不同的行重复出现，无法一眼看到“QQ → 手机号 → 微信 → 设备 → 群聊”的完整路径。
2. **表格列不是按查案顺序设计**：查到手机号后，你下一步是想看“这个手机号还能查出哪些 QQ/微信”，不是补“昵称、实名、登录时间”。
3. **信息密度假高**：登录地、昵称、实名、来源等字段挤占主要视野，但当前研判真正需要的只有关键 IP、账号链和社交扩展。
4. **线索扩展没有入口**：表里有一个账号，但没有“下一步去补它的手机 / IP / 同机账号 / 好友 / 群聊”的按钮。
5. **备注承担了系统职责**：红字、平台链接和人工判断全部被塞进备注，导致检索、汇总和报告无法自动化。

因此不能把截图优化成“更好看的 Excel”，而应当改成“**线索树 + 自动生成的全量表**”。

## 正确的主界面：一个案件，三块区域

```text
┌────────────────────────────────────────────────────────────────────────┐
│ 案件：XXX                                  [生成简报] [脑图] [全量表] │
│ 背景：______________________________________________                  │
│ 初始线索： [微信号 wxid_xxx] [+ 添加另一条初始线索]                   │
├────────────────────┬──────────────────────────────┬──────────────────┤
│ ① 我刚查到什么      │ ② 线索脑图（默认视图）        │ ③ 自动简报       │
│                    │                              │                  │
│ 当前：微信 wxid_xxx │      微信 wxid_xxx            │ 已录入：          │
│                    │      ├─ 手机号 138...         │ - 微信 3 个       │
│ [手机号]            │      │  ├─ QQ 2 个            │ - QQ 7 个         │
│ [关联QQ]            │      │  └─ 微信 1 个          │ - IP 4 个         │
│ [关联微信]          │      ├─ 登录 IP 1.2.3.4      │ - 群聊 5 个       │
│ [登录IP]            │      │  └─ 同IP账号 4 个      │                  │
│ [同机账号]          │      ├─ 同机账号 2 个        │ 当前主链：        │
│ [好友] [群聊]       │      └─ 群聊 3 个            │ 微信→手机号→QQ   │
│ [公开平台账号]      │                              │                  │
│                    │ 点枝条展开；点节点继续补查    │ 可继续补：        │
│ 结果：____________  │                              │ [该手机号的QQ]    │
│ [回车添加]          │                              │ [该IP的账号]      │
└────────────────────┴──────────────────────────────┴──────────────────┘
```

用户不需要来回切页。录入、看关系、看总结在一个屏幕内完成。

## 最关键的交互：查一个点，展开一枝

### 1. 先写背景和初始线索

新建案件只需要：

- **背景**：自由写，支持直接粘贴一段话；
- **初始线索**：例如微信号、QQ、手机号、IP、平台账号、群名中的任意一个或多个。

初始线索一输入，系统在中间生成根节点。没有“先建人员档案”“填实名”“选地区”的步骤。

### 2. 点当前节点，系统只问一个问题：你刚查到哪一类结果？

例如当前节点是 `微信 wxid_xxx`，左侧只显示最贴近这个节点的 6 个大按钮：

```text
[关联手机号] [关联 QQ] [关联微信]
[登录 IP]    [同机账号] [好友/群聊]
[公开平台账号] [关联团伙] [更多]
```

点击 `关联手机号` 后，不弹复杂表单，只出现：

```text
微信 wxid_xxx 关联的手机号： [________________]  [添加]
```

输入一个或粘贴多个号码，回车。系统自动：

- 新建或复用手机号节点；
- 在脑图上挂到当前微信下；
- 在全量表里新增一条关系；
- 右侧简报增加一句；
- 自动把“该手机号可继续补查的内容”推到下一步。

### 3. 连续结果要支持一把粘贴

很多时候你不是查到一个结果，而是一批：

```text
13800138000
13900139000
13700137000
```

或者：

```text
QQ: 123456789
QQ: 987654321
QQ: 55667788
```

输入框支持直接粘贴多行。用户只需先选一次 `关联 QQ` 或 `关联手机号`，系统自己拆行、去重、批量加枝。

如果结果是“同 IP 的账号一大堆”，不需要一条条点：

```text
当前：IP 1.2.3.4
结果类型：同 IP 登录账号
[ 粘贴账号列表 ]
[添加 28 个账号]
```

脑图上默认显示“同 IP 账号（28）”这个折叠枝，而不是把 28 个节点瞬间铺满。

## 不要把所有字段塞进一条账号

当前需求里真正影响研判主线的对象只有：

| 线索对象 | 第一版保留什么 | 第一版不强制显示什么 |
|---|---|---|
| QQ / 微信 / 平台账号 | 账号值、关联账号、手机号、IP、设备、好友、群聊 | 昵称、实名、登录时间、登录地点 |
| 手机号 | 号码、关联 QQ、关联微信、关联平台账号 | 归属信息、实名信息 |
| IP | IP 值、关联账号、关联设备 | 多个登陆地、冗长地理描述 |
| 设备 | 设备标识、同机账号 | 设备详情字段 |
| 群聊 | 群名称/ID、成员账号、共同群 | 群内无关资料 |
| 团伙 | 团伙名、关联账号/群聊/平台 | 不必要描述字段 |

你的判断是对的：

- **两个登录地，只留 IP 就够**；地点不是主对象；
- **实名、昵称、登录时间默认不要**；它们不是线索树的一等节点；
- **关联来源不应占主表**；最多作为节点详情里的可选小标签；
- **备注不能是主数据结构**；备注只是补充，不应该承担“关系”和“平台账号”的信息。

## 系统如何主动提示“接下来还要查什么”

它不替你查，也不展示抽象待办，而是在每个节点下面给出自然的“下一枝”。

### 账号节点的补查模板

```text
微信 / QQ / 平台账号
├─ 补关联手机号
├─ 补关联 QQ
├─ 补关联微信
├─ 补登录 IP
├─ 补同机账号
├─ 补好友
├─ 补群聊
├─ 补公开平台账号
└─ 补关联团伙
```

### 手机号节点的补查模板

```text
手机号
├─ 补关联 QQ
├─ 补关联微信
├─ 补关联平台账号
└─ 看已关联账号的共同群 / 同机 / 同 IP
```

### IP / 设备节点的补查模板

```text
IP / 设备
├─ 补关联账号
├─ 将账号按 QQ / 微信 / 平台分组
├─ 看共同群聊
└─ 看共同手机号
```

### 群聊节点的补查模板

```text
群聊
├─ 补群内账号
├─ 看群内账号的手机号 / IP / 设备交集
├─ 看成员共同群
└─ 标记可能关联团伙
```

提示只在当前枝没有填过时出现。填完自动消失，避免变成密密麻麻的任务列表。

## 两种图：脑图看主线，关系网看交叉

### 默认：XMind 式线索脑图

默认按“从初始线索向外展开”的树形显示，最适合你边查边填：

```text
初始微信 wxid_xxx
├─ 关联手机号
│  ├─ QQ A
│  ├─ QQ B
│  └─ 微信 C
├─ 登录 IP
│  └─ 同 IP 账号（折叠）
├─ 同机账号
├─ 好友
├─ 群聊
│  ├─ 群 1
│  └─ 群 2
└─ 公开平台账号
```

同一个对象在多条路径里出现时，脑图上显示为“引用节点”，点击会跳回它的主节点。这样既不乱，也不会丢失交叉关系。

### 切换：关系网

当需要看“哪些账号因为同 IP、同设备、共同群互相连在一起”时，再切到关系网。系统自动聚合：

- 一台设备连接的账号簇；
- 一个 IP 连接的账号簇；
- 一个手机号连接的 QQ/微信/平台账号链；
- 一组共同群聊关系；
- 多个平台账号与团伙的连接。

这张图不是录入入口，而是研判视图。

## 全量表不是 Excel 原样复刻

全量表由系统从脑图自动生成，保持只有四列：

| 当前对象 | 关系 | 关联对象 | 可继续展开 |
|---|---|---|---|
| 微信 wxid_xxx | 关联手机号 | 13800138000 | QQ 2、微信 1、平台账号 3 |
| 手机号 13800138000 | 关联 QQ | 123456789 | IP 1、群聊 2 |
| QQ 123456789 | 同机登录 | 设备 A1B2 | 同机账号 4 |
| QQ 123456789 | 加入群聊 | 群 887766 | 群成员 28 |
| IP 1.2.3.4 | 关联账号 | 微信 wxid_xxx | 共同账号 5 |

规则：

- 不显示实名、昵称、登录时间、最后登录地等当前不需要的字段；
- 不重复展开父级信息；
- 同类结果聚合成数量，例如“群成员 28”；
- 点“可继续展开”直接回到脑图对应枝；
- 可一键导出 Excel，但 Excel 只是导出物，不再是工作台本体。

## 自动生成的“可调查总结”

报告需要分成两层：**当前明确关系**和**下一步可继续查的枝**，不要把所有字段机械罗列。

```markdown
# 线索情况简报

## 背景
{用户输入的背景}

## 初始线索
本案以微信账号 wxid_xxx 为起点展开。

## 当前账号链路
- 微信 wxid_xxx 关联手机号 13800138000。
- 手机号 13800138000 进一步关联 QQ 账号 123456789、987654321 及微信账号 wxid_abc。
- QQ 账号 123456789 与微信 wxid_abc 同机登录于设备 A1B2。

## 社交关系扩展
- 当前已关联 2 个群聊，其中“群 887766”包含 28 个已录入账号。
- 账号链中存在 1 个共同 IP 节点，已关联 5 个账号。

## 当前核心线索
- 手机号 13800138000：连接 QQ、微信及平台账号的核心身份节点。
- 设备 A1B2：连接多个账号的共同设备节点。
- 群 887766：当前社交关系的主要扩展节点。

## 可继续补查
- 补录手机号 13800138000 关联的平台账号。
- 展开 IP 1.2.3.4 的其余关联账号。
- 展开“群 887766”成员与其他群聊的交集。
```

报告完全从用户已填内容生成；“可继续补查”只来自当前树上还没有展开的标准分支。

## 开源项目重新排序

没有找到一个项目可以直接给你上述完整交互，但方向已经比前一版更清晰：

1. **Casebook**：最接近“案件里不断加东西、加连接、最后导出”的工作区结构；可借它的案件、节点、连接、时间线和导出组织方式，但 UI 必须大幅改轻。
2. **Flowsint**：最接近“点击一个节点继续扩展”的图谱体验；适合借图谱画布、节点详情、局部展开和关系探索，不以它的自动分析能力为重点。
3. **Mind-Elixir / React Flow**：不是案件项目，但适合实现 XMind 式默认脑图。前者偏脑图交互，后者适合把脑图和关系网做成一个可切换画布。
4. **Cytoscape.js**：适合关系网模式、共同群/同机/同 IP 的自动聚合；不适合做默认录入交互。
5. **POLE**：只作为内部关系分类的参考，不直接露给用户。

推荐的拼装方式不是“改一个开源平台”，而是：

```text
Casebook 的案件工作区思路
+ Flowsint / React Flow 的节点展开与图谱交互
+ Mind-Elixir 的脑图折叠体验
+ Cytoscape.js 的关系网聚合视图
+ 自己定义的账号/手机号/IP/设备/群聊/团伙快速录入模板
```

第一版甚至可以不引入图数据库：`实体表 + 关系表 + 脑图/关系网前端` 足够做出真正好用的产品。

## P0 的边界：只做真正减负的东西

### 必做

- 背景 + 初始线索；
- 当前节点的一键“下一枝”按钮；
- 单值和多行粘贴录入；
- 自动去重、自动复用节点；
- 默认线索脑图；
- 关系网切换；
- 自动全量表；
- 自动简报；
- 账号、手机号、IP、设备、好友、群聊、平台账号、团伙 8 类节点。

### 先不做

- 实名、昵称、登录时间、地理位置的大字段表；
- 多层审批、复杂任务系统；
- 文档自动抽取；
- 复杂报表；
- 数据接入和自动查询。

## 产品验收：用你的真实习惯判断

P0 不是看功能列表，而是看以下动作是否成立：

1. 从“我查到一个微信号”开始，**10 秒内**建好根节点；
2. 从“我查到这个微信关联 4 个手机号”开始，**一次粘贴**完成，不逐条填表；
3. 从“这个手机号又牵出一堆 QQ”开始，脑图默认只显示“关联 QQ（18）”，不炸图；
4. 点“关联 QQ（18）”才展开这一枝；
5. 查到群后只要粘贴成员账号，系统自动把群和账号挂上；
6. 任何时刻点“生成简报”，都能得到当前主链、核心节点和下一步可展开分支；
7. 导出的全量表不会再有截图中那种重复账号、无关字段和备注承担一切的问题。
