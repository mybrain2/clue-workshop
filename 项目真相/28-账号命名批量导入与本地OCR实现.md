# 账号命名、批量导入与本地 OCR 实现

> 版本：0.6.0。状态：已实现、构建与回归验证。

## 本轮实现

### 节点显示与备注

- 节点小圆点使用对象类型色；卡片边框和背景使用同一类型色的低透明度版本，避免整块重色干扰阅读。
- 节点第一行显示 `对象类型 · 主值`，例如 `QQ号 · QQ 940001`；第二行显示可选账号命名/昵称，例如 `昵称-甲`。
- 有账号备注但未命名时，卡片显示低干扰“有备注”文字和类型色小点；右侧当前对象区可展开完整备注。
- 编辑对象窗口增加“账号命名 / 显示别名”。

### 案件级信息与路径栏

Case 新增：

- `background`：案情简介；
- `police_disposal`：警方处置；
- `current_status`：当前现状；
- `path_lanes`：调查路径分栏 JSON。

工作台顶部“案件概览”统一编辑四项。路径视图顶部依据 `path_lanes` 渲染六个可定制分栏；它只调整阅读标注，不改变底层多对多关系。简报导出固定输出“案情简介 / 警方处置 / 当前现状 / 线索概括”。

### 批量导入

“批量导入”位于工作台顶部，也位于当前对象快捷操作内。

输入来源统一生成候选行，再由同一受控关系事务写入：

- **粘贴**：换行、Tab、英文/中文逗号；
- **Excel / CSV**：读取首个工作表，预览前 8 行；可选“账号/主值列”和“昵称/命名列”，可声明首行为表头；
- **截图**：图片只在本机进入 macOS Vision OCR；识别行进入可编辑候选文本，用户删除界面噪声或修正结果后才确认写入。

写入前执行空值剔除与主值去重；新对象可同时写入 `display_name`。已存在对象不会被导入动作覆盖命名，避免表格误导入覆写人工结论。

### OCR 取舍

调研确认 PaddleOCR / PP-Structure 是中文复杂布局与表格 OCR 的成熟开源选择，但将其与 Python/模型一起塞入当前轻量 macOS 安装包会提高体积、模型版本和分发复杂度。0.6.0 先使用系统内置 Vision：

- 无网络、无上传、无额外模型下载；
- 原生 helper 随 `.app` 打包；
- 实测在桌面截图上返回 169 个文本行；
- 不承诺自动判断哪一列是账号，必须经用户预览确认。

后续若收到包含复杂表格/低清中文截图的脱敏样本，按真实准确率决定是否引入 PaddleOCR sidecar，而不是先背一个大模型包。

## 验证

1. CLI 更新案情简介、警方处置、当前现状和六个路径栏，`case-get` 回读一致；
2. MCP `clue_update_case_overview` 更新同一字段并回读一致；
3. 账号 `QQ 910001` 写入显示名“首批外联 QQ”、备注和重点标记，回读一致；
4. 生成含“账号 / 昵称”两列 Excel；表头跳过、账号列去重后得到两个值；
5. 以 `displayNames=[昵称-甲, 昵称-乙]` 批量写入，回读 `QQ 940001 → 昵称-甲`、`QQ 940002 → 昵称-乙`；
6. 运行内置 `vision-ocr` 对 PNG 截图识别，返回 169 行；
7. 90 实体 / 89 关系多跳回归，以及 CLI/MCP 回归均通过；
8. 简报导出实际包含三段案件备注；
9. 前端、Rust、release bundle 构建通过。
