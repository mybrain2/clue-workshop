# 99 - 20260923 验收遗留清理与未连接根治（unavailable 阻止提交）

## 背景

用户在回收站截图发现「方向v2逻辑圈-可删除3」案件整批 6 个节点全部在"未连接对象"区，质疑验收"全部通过"的真实性。

复盘结论（不辩解）：

1. **截图案件是昨天方向v2验收的临时案件**（脚本 CLI 直导、`currentSource: None`，故意验证"未接入形态"），验收后只进了回收站没有彻底删除，用户翻回收站时看到了这个"半成品"。
2. **产品存在真实缺口**：`accessStatus === "unavailable"`（查询起点不在案件中、又没有可勾选接入的选中对象）时，UI 只显示提示文案但**不阻止提交**，用户确认后整批落库即成未连接对象。大哥/示例1 案各 497 个孤立实体就是这么来的（2026-09-20 导入 ai群.csv 时无选中对象直接提交）。
3. "全部通过"声明中"未接入时属预期"只验证了脚本侧行为，没有覆盖"真实用户顺手点确认"的路径——测试片面，用户质疑成立。

- 第二步接入状态文案："缺少可用接入对象：导入结果将出现在未连接区域" → "缺少可用接入对象：**已阻止提交**"。

- 顺带修复：`initialSmartText` 携带表格打开弹窗时直接进入第二步"检查结果"（此前停在第一步且 textarea 为空，quick-table 桥接路径看不到接入状态）。

新测试 `ImportDialog.unreachable-block.test.tsx`（3 用例）：

1. 无选中对象 + 严格群列表计划 → 第二步显示"已阻止提交"、按钮 disabled。
2. 选中主链对象（bridge-available）→ 不出现阻断文案、默认勾选接入。
3. 阻断只作用于 review 步骤且不与 batchErrors 叠加。

## 设计边界（保持不变）

- 计划层 `canSubmit` 不动：unavailable 时计划本身合法可构建（数据没错，只是没接入），阻断在 UI 提交层。CLI/import_plan 后端不加此限制——脚本化导入允许显式制造未接入形态（验收就是靠它验证的），责任在调用方。
- 桥接勾选仍默认勾上（bridge-available 时），用户主动取消勾选属显式选择，不阻断（尊重用户）。
- reuse-existing / query-origin 形态不受影响。
