# 语义路径、案件包与局部关系网

> 版本：0.7.0。状态：已实现、跨包验证与发布校验完成。

## 设计结论

### 调查路径不是对象类型流水线

此前的固定列“联系方式 → 账号关系 → 设备与网络 → 社交与组织”错误地暗示：手机号一定先于账号、位置和账号同等重要、所有案件都按相同顺序推导。这不符合实际。

本版改为四种**角色**：

| 角色 | 对象 | 在图上的位置 |
|---|---|---|
| 推导主线 | 主体、微信、QQ、平台账号，以及由关系继续扩展的对象 | 顶部主线，按真实关系方向展开 |
| 关联条件 | 手机号、IP、设备 | 仍在主线中；它们可能是账号的同级证据，也可能是推导下一个账号的条件 |
| 背景说明 | 活跃位置、机房 | 单独下沉到“背景说明”轨道，不与账号主线竞争视觉权重 |
| 社群组织 | 群聊、组织 | 按真实关系留在主图，可形成独立分支 |

路径顶部不再显示假的固定分栏，而是显示“账号与关联条件主线”；背景轨道只在存在位置/机房时出现。关系标签本身保留为证据语义。

高连接分支按“父节点 + 关系标签 + 对象类型”聚合，聚合节点承载关系和数量，边不再重复堆叠长标签。路径默认每组留一个代表对象和一个可展开聚合。

### 主体关系网是否保留

保留，但职责收窄：

- **调查路径**：回答“案件是如何沿关系向外展开的”；
- **主体关系网**：回答“当前对象周围一跳/两跳有哪些关联面、共同条件和聚集点”。

它不是第二条调查路径，也不应作为默认视图。默认仍为调查路径；关系网只在核查某个具体对象时使用。

这个判断参考了 OSINT Workbench / Maltego 类链接分析工具的共同原则：节点和关系类型必须具有语义，网络图用于局部邻域检查与中心性判断，而案情叙事要依赖有方向的关系主线。Kanvas 的可移植案件文件原则则用于案件包设计。

## 一键关联

右侧直接录入调整为准确的高频入口：

- 关联 QQ；
- 关联微信；
- 关联手机号；
- 关联 IP；
- 更多类型（设备、群聊、位置、组织）；
- 批量导入。

点击后预置对应类型和默认关联标签，直接输入即可。完整表单仍提供：多值粘贴、全部对象类型、可编辑标签、扩散方式、自定义类型、备注/推导说明。

## 失效、排除与重点

对象状态不再只存于编辑表单：

- **待核实**：琥珀色虚线边框与“待核实”标记；
- **已失效**：灰色虚线边框与“已失效”标记；
- **已排除**：红色虚线边框与“已排除”标记；
- **重点**：节点右上显示“重点”；
- 失效/排除关系同步使用状态色和虚线。

CLI 回归实际写入并回读了“对象已失效 + 重点、关系已排除 + 强调”。

## 可交换案件包

“生成案件材料”改为先选择保存位置，输出统一文件夹：

```text
案件名-时间戳/
├── 案件包.json      # 软件可重新打开的完整结构化数据
├── 案件简报.md      # 人可读案情/处置/现状
├── 关系脑图.svg     # 可在常规工具打开的关系图
└── 全量关系.csv     # 通用关系表
```

“打开案件包”选择 `案件包.json` 后，将案件复制进本机案件库并生成新 ID，不覆盖既有案件。真实验收：从“北岸账号关联线索”导出包、导入后回读 13 实体/11 关系，随后将测试副本移入回收站。
