## 2. 三件套导出

默认导出目标：

1. `.cluecase v2`：跨电脑完整还原案件、实体、关系、颜色、重点、附件、附件说明和关联。
2. `.xmind`：原生 XMind 文件。
3. `_案情说明.md`：人类可复制、AI 可理解的自包含案件事实说明。

### XMind 当前实现与可读性调整

- 使用官方 `xmind` SDK sidecar 生成，不再手写 ZIP 容器。
- 脑图按真实有向关系 `source → relation → target` 展开，不按对象类型分组。
- 多父、交叉、环与孤立对象均保留；不得为了树形显示删除或反向关系。
- 对象标题改为“类型 · 值”；关系标题改为“→ 关系标签”；完整 ID、状态、备注、扩散方式与重点放在多行 note 中。
- 用户提供的 `脱敏多跳回归案件-20260904-102011.424-bbc372ab-b617-4d63-9c1c-37562c487a61.xmind` 已解析：文件为有效 ZIP，包含 `content.json`、`metadata.json`、`content.xml`、`manifest.json`，其拓扑已是主体簇→初始线索→微信→手机号→QQ→IP→机房等真实关系链。该文件生成于可读性调整前，需由最新构建重新导出验证。

## 3. 稳定性修复

已完成：

- `App.refresh()` 添加请求序号与当前案件 ID 防护，避免切案、轮询、导入并发回写旧案件。
- Excel/CSV 导入增加文件大小、工作表、空数据校验与异常提示。
- 附件选择、说明更新、删除增加失败提示；固定附件限制为 512 MB。
- 图谱节点偏移 localStorage 严格校验，非法缓存清除，避免渲染异常。
- `.cluecase` 导入将 revision 更新纳入数据库事务；仅在事务未提交时清理附件目录，避免已提交附件被误删。

未关闭：

- 超深关系链的 XMind 构造尚需改为迭代式，避免极端数据递归栈溢出。
- 附件 SHA-256 尚需改为真正流式哈希，避免超大文件内存峰值。
- v1 JSON 案件包仍需补充重复 ID、错误关系引用和数组限额的严格预校验。
- 必须用最新 `.app` 实际导出 XMind，并在用户 XMind 客户端打开验证；构建/ZIP 检查不能替代用户客户端验收。
