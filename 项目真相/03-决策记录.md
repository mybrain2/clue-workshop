# 决策记录

## D-001：案件是一级工作区

**已定**：一个案件一个独立工作区，长期保存、可切换、可归档、可恢复。  
**原因**：调查上下文、背景、初始线索、关系图、视图状态和简报必须跟随案件，不应和其他案件混在一起。  
**影响**：所有节点、关系、快照与导出必须带 `case_id`。

## D-002：底层使用多对多关系图，不使用脑图作为事实存储

**已定**：节点和关系表是权威数据；XMind 式线索树只是调查路径视图。  
**原因**：账号、手机号、IP、设备、群聊与主体簇会分叉、合流、回连，一个节点可能有多个父级。  
**影响**：脑图组件不能决定数据模型。

## D-003：主画布选 AntV G6，Mind Elixir 是辅助视图

**已定**：G6 作为树、关系网与聚合总览的主画布候选；Mind Elixir 只用于脑图阅读/导出增强。  
**原因**：G6 更适合多对多图、聚合节点、布局切换和 React 自定义节点；Mind Elixir 更适合层级树，不能单独承接回连网络。  
**待验证**：G6 分支折叠、Combo 聚合和真实群聊高连接数据性能。

## D-004：不 fork Casebook 或 Flowsint

**已定**：只参考其案件工作区、局部展开、导出和节点详情思路。  
**原因**：直接 fork 会把通用案件管理或 OSINT 工作流带进来，增加手工快速录入的阻力。  
**影响**：自建轻量产品壳，按实际输入习惯定义节点和“下一枝”按钮。

## D-005：快速录入优先于字段完整

**已定**：主流程只要求关系和值；备注、时间、来源等为可选补充。  
**原因**：用户的核心痛点是边查边填太慢，而不是字段不够多。  
**影响**：表单不能把非必要字段设为阻塞项。

## D-006：高连接关系默认聚合

**已定**：对同 IP、同设备、群成员、多账号等高连接关系，默认显示数量枝，例如“同 IP 账号（37）”。  
**原因**：全量节点直接铺开会破坏可读性和性能。  
**影响**：展开/收起和局部加载是 P0 必须验证的能力。

## D-007：独立于 Obsidian 与 ClueProbe

**已定**：本产品不与 Obsidian 或 ClueProbe 连接。  
**原因**：用户要求独立边界和独立复盘能力。  
**影响**：采用自己的数据库、文档真相库、模块地图和导出格式。

## D-008：设计方法采用 Impeccable，不为装 Skill 引入低质量依赖

**已定**：使用已加载的 Impeccable 设计约束，并以官方组件文档和样本 PoC 验证；市场中未找到足够贴合且可信度更高的产品设计 Skill。  
**原因**：SkillHub 搜索结果相关度低；Vercel Skills 找到的信息架构和 UI/UX 候选可供后续评估，但尚未通过安全审查，不安装。  
**影响**：当前设计坚持渐进披露、低认知负担、清晰状态、可撤销、可复盘和克制的编辑式调查画布。

## D-009：Demo 采用单画布、前端本地持久化的最小验证方案

**已定**：Demo 使用 React + TypeScript + AntV G6 + 浏览器本地持久化；不引入后端、Neo4j、Mind Elixir、Cytoscape.js 或模型服务。  
**原因**：当前首要风险是“复杂账号关系能否在少输入、可聚合、可切换案件的画布中被读懂”，而不是服务端或智能能力。  
**影响**：Demo 先验证案件切换、批量粘贴、图聚合、树/网/表同源和简报同步；通过后再进入正式 P0 存储与服务端实现。

## D-010：默认画布极简，语义详情按需呈现

**已定**：画布默认只展示主路径、对象核心值、类型色点和状态点；角色、备注、扩散方式与推导说明放入选中对象的 Inspector 或选中关系的编辑面板。  
**原因**：首轮“语义全显”界面造成节点卡、关系标签和边框同时竞争注意力，用户反馈为又丑又乱。  
**影响**：不再以更多标签解决可读性；关系文字仅局部显示，默认画布只服务于回忆案件主线。

## D-011：采用审计通过的 Apple / Taste 设计规则

**已定**：已安装 `apple-design`、`redesign-existing-projects`、`minimalist-ui` 三个技能；以 Apple 的 Clarity / Deference / Depth 和 Taste 的低方差、高密度、低动效重设计规则约束后续 UI。  
**原因**：用户要求接近 iOS/macOS 的干练专业感；审计未发现自动执行、敏感读取、网络外送或供应链风险。  
**影响**：系统字体、暖中性色、轻材质层级、局部语义色、可中断/克制反馈成为默认；不采用实验性 Taste 默认 v2 作为唯一规则。

## D-012：回归第一版直接录入架构

**已定**：恢复“左侧案件库 / 中部画布 / 右侧当前对象与直接添加按钮”的第一版信息架构；第二、三版的语义能力保留，但不再改变主操作路径。  
**原因**：用户明确反馈第一版的添加逻辑和主界面更清楚，问题是视觉质量而非交互直达性。  
**影响**：选中节点后直接显示“添加手机号、添加QQ号、添加微信号、添加IP、添加群聊”等按钮；不增加单独的对象类型选择层。详情仍在右侧按需编辑。
