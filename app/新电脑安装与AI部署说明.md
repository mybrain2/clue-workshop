# 线索研判：新电脑安装与 AI 部署说明

> 适用对象：拿到**发布包**的主体机器及其协作 AI。本文不要求、也不应接收本项目的开发源码、项目真相 Markdown、历史版本、测试截图或任何既有案件数据。

## 交付物最小集

交付给新电脑时只需要以下文件：

```text
线索研判-<版本>.dmg                 # 推荐安装入口
线索研判_简要操作手册.svg             # 给使用者看的单页操作海报
新电脑安装与AI部署说明.md             # 本文
```

可选交付（仅在主体需要自动化时提供）：

```text
automation-<版本>/
├── clue-workbench-cli
├── clue_workbench_mcp.py
└── clue-workbench.mcp.json
```

**不要交付**：`项目真相/`、开发 README、源码 `src/`、`src-tauri/`、历史 App/DMG、QA 截图、数据库副本、旧案件包或其他人的案件文件。

## 一、主体机器的安装步骤（macOS）

### 前提

- macOS 12 或更高版本。
- 主体对本机“应用程序”和个人资料目录有正常写入权限。
- 不需要安装 Node、Python、Rust、数据库服务或任何开发环境。

### 安装

1. 双击 `线索研判-<版本>.dmg`。
2. 在打开的磁盘映像中，将 `线索研判.app` 拖到 **应用程序（Applications）** 文件夹。
3. 如需桌面入口：在“应用程序”中选中 `线索研判.app`，按住 Option + Command 拖到桌面，生成别名；不要把 App 主副本长期放在 DMG 或桌面下载目录。
4. 首次打开时，如 macOS 拦截：按住 Control 点击 App，选择“打开”，在确认框再次选择“打开”。
5. 打开后新建一个空案件，输入任一首条线索，确认左侧案件列表和中间图谱出现内容。

### 升级

1. 退出正在运行的 App。
2. 将新版 App 拖到“应用程序”覆盖旧版。
3. 再打开 App。**不要删除本机数据目录**，升级不会清理案件。
4. 开启后检查一个既有案件能正常显示，再删除旧 DMG。

## 二、案件数据存放位置

应用的数据不在 `.app` 内，也不在 DMG 内，而在当前 macOS 用户的个人资料目录：

```text
~/Library/Application Support/线索研判数据/
├── casework.sqlite3       # 当前主体的案件数据库
├── attachments/           # OCR 临时目录与后续附件目录
├── exports/               # 默认导出材料
├── backups/               # 预留目录
├── snapshots/             # 预留目录
└── logs/desktop-runtime.log
```

规则：

- 每个 macOS 用户拥有自己的本地案件库；不同机器、不同用户默认互不共享。
- 不要手工用 SQLite 工具改 `casework.sqlite3`；使用 App、案件包、CLI/MCP 才能保持撤销、快照和同步一致。
- 卸载 App 不会自动删除该目录；如果主体要清除数据，必须自行确认并备份后处理。
- 不应把该目录与开发文件、项目真相或他人数据一起交给新主体。

## 三、案件迁移与备份

### 推荐方式：案件包

从旧电脑：

1. 打开目标案件。
2. 右侧“导出当前案件”选择保存位置。
3. 得到一个案件材料文件夹，包含：

```text
案件名-时间戳/
├── 案件包.json
├── 案件简报.md
├── 关系脑图.svg
└── 全量关系.csv
```

到新电脑：

1. 安装并打开线索研判。
2. 在右侧“导出当前案件”区域点击 **打开案件包**。
3. 选择 `案件包.json`。
4. 系统导入为一份新案件，不覆盖新电脑已有案件。

### 整机迁移（仅主体明确授权时）

如果主体要求把该 macOS 用户的全部案件迁到新电脑：

1. 先退出线索研判。
2. 复制整个 `~/Library/Application Support/线索研判数据/` 目录到加密介质。
3. 在新电脑对应用户下恢复到相同路径后再启动 App。
4. 恢复前先备份新电脑已有同名目录，避免覆盖。

整机迁移会携带该主体的全部案件；不要用于向其他人分发，也不要将其与开发包混合。

## 四、给协作 AI 的部署指令

新电脑上的 AI 只需要知道“如何安装和协助使用”，不需要本项目开发上下文。

### AI 必须遵守的边界

1. 不索取、不读取、不创建本项目的开发 Markdown、项目真相、历史测试文件或源码。
2. 不读取、上传、汇总或转发主体的 `casework.sqlite3`、案件包、导出材料或截图，除非主体在当前对话中明确授权某一个具体文件。
3. 不直接修改 SQLite 数据库；通过 App 的可见操作协助，或经主体授权配置可选 CLI/MCP。
4. 不将案件数据发送到云端、第三方服务或其他机器。
5. 发生异常时，优先让主体重启 App、查看可见错误提示；不要尝试删除数据目录作为“修复”。

### AI 可执行的首装验收

- 确认 App 位于“应用程序”目录且可启动。
- 确认可新建测试案件、添加一条关联、撤销一次、导出到主体指定位置。
- 确认数据目录存在，但不读取数据库内容。
- 向主体展示 `线索研判_简要操作手册.svg`。

### 可选：本地自动化配置

只有主体明确要求 AI 通过本地 CLI/MCP 操作案件时，才提供 `automation-<版本>/`。配置文件 `clue-workbench.mcp.json` 中的路径必须改为新电脑实际绝对路径；不得沿用交付机器的路径。

配置完成后先执行“health / 只读列出案件”验证；写入操作必须得到主体明确指令。永久删除不应开放给自动化。

## 五、使用者的最短上手路径

1. 新建案件：案件名 + 第一条线索。
2. 点击图中对象。
3. 从右侧选择 QQ、微信、手机、IP、群聊等类型，直接粘贴结果。
4. 单击节点或关系查看局部高亮；关系双击才编辑。
5. 需要批量数据时使用 Excel/CSV/图片导入，确认预览后写入。
6. 要交接时导出案件包；另一台电脑通过“打开案件包”导入。

- [ ] App 已放入“应用程序”，不是仅停留在 DMG。
- [ ] 首次启动成功，创建空案件正常。
- [ ] `~/Library/Application Support/线索研判数据/` 已创建。
- [ ] 点击节点能选中，右侧录入卡跟随当前对象启用。
- [ ] 导出并重新导入一个测试案件成功。
- [ ] 交付目录中没有源码、项目真相或他人案件数据。
